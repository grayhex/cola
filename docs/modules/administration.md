# Администрирование и настройки

[Оглавление](../README.md)

## Назначение

Админка управляет продуктом без редактирования исходников: оформление, пользователи, справочники, парсер, карты, квоты, игровые правила и модерация. Это UI над несколькими доменными settings API, а не единый словарь всех серверных секретов.

## Точки входа

`/admin`; группы **Система, Дизайн, Пользователи, Механики, Каталог**. Общий контроллер — [admin.jsx](../../app/admin/admin.jsx), HTTP — [admin route](../../app/api/admin/%5B...path%5D/route.js). Resolver, GPX и gamification имеют собственные API/редакторы; их настройки не обязаны сохраняться общей кнопкой оформления.

### Рабочее пространство «Дизайн»

Компактные вкладки разделяют параметры поведения и выбор файлов:

| Вкладка | Содержание |
| --- | --- |
| Внешний вид | Тема по умолчанию, акцент, предпросмотр |
| Главная страница | Картинка рядом с заголовком, заголовок и описание hero |
| Меню | Название, видимость и порядок разделов |
| Изображения и брендинг | Favicon, фотографии по умолчанию, иллюстрации контента |
| Медиатека | Превью, поиск, использование, точечное удаление и очистка |
| Тексты | Копирайтинг сайта и подписи кнопок мастера |
| О проекте | Содержание и видимость блоков |

Черновик и общая кнопка сохранения принадлежат контроллеру. Переключение вкладок не сбрасывает выбранные файлы. Во время загрузки и сохранения переходы блокируются. Сообщение об успешном сохранении появляется после обновления медиатеки, одновременно с разблокировкой управления.

[design-graphics.js](../../lib/design-graphics.js) описывает слоты иллюстраций контента. UI использует встроенные векторные иконки и единственный локальный шрифт. Настройки прежнего оформления и импорт наборов иконок удалены; миграция `016_product_ui.sql` очищает их из БД.

## Данные и основные функции

[site.js](../../lib/site.js): `getSite`, `audit`, `updateManagedUser`. [admin-validation.js](../../lib/admin-validation.js) задаёт разрешённую форму настроек, каталога и пользователя. [site-assets.js](../../lib/site-assets.js) собирает ссылки на используемую графику и категории использования.

`site_settings` и `site_catalog` сохраняются с номером версии. Запрос с устаревшей версией возвращает конфликт, а не молча перезаписывает изменения другого администратора. Gamification хранит собственный JSON и блокирует строку на обновление; это не тот же механизм optimistic version, что у оформления. Настройки Resolver имеют свой version в его хранилище.

## Сценарий и ограничения

Оформление: загрузить/выбрать asset → изменить черновик → сохранить версионированные settings. Загрузка файла сама по себе не публикует его во всех слотах. У achievements собственная кнопка сохранения правил, картинок и описаний. Листание модерации не должно уничтожать этот черновик.

Административные запросы требуют текущего admin и допустимого Origin для записи. Изменения пользователей учитывают защиту административных ролей; удаление требует подтверждение. Блокировка влияет на публичную выдачу, а не просто скрывает кнопку в UI. Важные действия записываются в `admin_audit`.

Медиатека хранит UUID-ресурсы в photos volume. Загрузка иллюстрации проходит проверку формата и размеров. Все картинки получают серверные имена.

### Безопасная очистка медиатеки

`GET /api/admin/assets/library` возвращает файлы с категориями использования, включая иллюстрации контента, рекордов и достижений. Клиент дополнительно защищает назначения из текущего несохранённого черновика и опубликованных настроек. Снятие назначения в черновике ещё не делает опубликованное изображение доступным для удаления: сначала нужно сохранить настройки.

`DELETE /api/admin/assets/library` принимает явный список `ids` (1–500 UUID). Кнопка очистки показывает подтверждение и отправляет только снимок выбранных неиспользуемых файлов, пакетами по 200. Изображения пользовательских велосипедов и аватары не входят в `site_assets` и не затрагиваются.

[site-asset-library.js](../../lib/site-asset-library.js) блокирует запрошенные строки `site_assets` в порядке UUID через `FOR UPDATE`, затем заново читает назначения сайта и наград. Используемые или уже удалённые файлы попадают в `skippedIds`. Сохранение settings и наград берёт `FOR SHARE` в таком же порядке: проверка назначения не может одновременно пропустить удаляемый файл.

Удаление записей и аудит `asset.delete` выполняются в одной транзакции, удаление файлов с диска — только после её успешного завершения. Ошибка удаления с диска, кроме уже отсутствующего файла, возвращает `cleanupWarning` и записывается в серверный журнал. При частичном сетевом сбое клиент сообщает число уже удалённых записей и обновляет список. Сервер не доверяет клиентскому утверждению, что файл не используется.

Не вводите серверный OAuth secret в поле публичного ключа карты. Внутренний адрес Resolver берётся из окружения, не из произвольного admin URL. Скрытие пункта меню не закрывает соответствующий API.

## Расширение и проверки

Новая настройка требует default, validation, корректного GET/PUT, защиты от потери старых полей и подключения к потребителю. Для asset-ссылки обязательно обновите проверку использования при удалении и единый каталог редакторов; для versioned settings — тест конфликта. Административное действие должно оставлять понятный аудит.

`node --test tests/admin-design.test.js` проверяет разрешённые слоты, строгую схему, защиту черновика и порядок блокировок/повторных проверок очистки. SQL-проверки этого набора используют тестовый адаптер, а не живую БД.

Для приёмки в браузере: изменить тему → выбрать изображение контента → вернуться и сохранить; удалить неиспользуемый файл, проверить отказ для назначенного и для награды. Проверить узкий экран, клавиатуру, подтверждение/отмену и устаревший снимок второго администратора. Полные HTTP/браузерные проверки дополняют unit-тесты.
