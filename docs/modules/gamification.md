# Награды, рекорды и реакции

[Оглавление](../README.md)

## Назначение

Модуль разделяет **награду**, которая остаётся у человека навсегда, и **рекорд**, который держит один велосипед, покатушка или участник, пока его не обойдут. Реакции сообщества дополняют лайки и участвуют в отдельных рекордах. С #106 и награды, и рекорды — **правила**: администратор собирает их из проверенных метрик без кода.

## Точки входа

`/records` с вкладками «Рекорды» и «Награды» (`?tab=awards`); на странице велосипеда, в профиле и в `/account?tab=achievements` — два отдельных блока «Рекорды» и «Награды» (в кабинете ещё «Следующая вершина» с прогрессом); блок «Рекорды» на главной; Админка → Механики → Награды и рекорды.

API: `/api/game/records` (рекорды, награды с числом получивших и последним видимым получателем, параметры рейтинга), `/api/game/me`, `/api/game/profiles/<username>`, `/api/game/bikes/<id>`, `/api/game/bikes/<id>/reactions/<kind>`; для администратора `/api/game/admin/settings`, `/api/game/admin/rules` (GET/PUT), `/api/game/admin/image-prompt` (GET/PUT), `/api/game/admin/recalculate` (POST), `/api/game/admin/bikes`.

UI: [records.tsx](../../app/ui/records.tsx), [records.module.css](../../app/ui/records.module.css), [achievements.tsx](../../app/ui/achievements.tsx), [achievement-art.tsx](../../app/ui/achievement-art.tsx), [редактор правил](../../app/admin/gamification.tsx), стили — [game.css](../../app/styles/game.css).

## Каталог метрик

[game-metrics.ts](../../lib/game-metrics.ts) — единственный список того, из чего собираются правила. У метрики есть предмет (`bike`, `ride`, `user`), единица, группа для страницы рекордов, допустимые фильтры и отметка, годится ли она для награды, для рекорда или для обоих.

| Группа               | Метрики                                                                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Стоимость            | цена (только рекорд, только если владелец её показывает)                                                                                 |
| Вес                  | вес велосипеда (только рекорд, в границах из параметров рейтинга)                                                                        |
| Велосипед            | модельный год (рекорд), детали с ключевыми словами (награда), публичные велосипеды, категории                                            |
| Комплектация         | детали у велосипеда с фото (награда), заполненность и прокаченность (рекорды)                                                            |
| Покатушки            | дистанция, набор высоты, средняя и максимальная скорость покатушки; число покатушек, километры за 30 дней, месяцы с покатушками в году   |
| Журнал               | записи журнала, записи об обслуживании                                                                                                   |
| Признание сообщества | лайки, реакции «Безумие», «Чистая сборка», «Хочу такой», участники с реакциями, лайки всех велосипедов владельца, подписчики, обсуждения |

Фильтры: тип велосипеда (`category`), минимальная дистанция покатушки (`minDistanceKm`), ключевые слова в названии детали (`keywords`, только буквы, цифры, пробел и дефис — слова подставляются в регулярное выражение SQL как есть).

Значения считают SQL-функции из [027_game_rules.sql](../../db/027_game_rules.sql): `game_bike_values`, `game_ride_values`, `game_user_values`. Рекорды велосипедов считаются по общему снимку рейтинга (`leaderboardSQL` + `rankBikes` в [gamification.ts](../../lib/gamification.ts)), рекорды покатушек и участников — теми же SQL-функциями.

## Правила

Таблица `game_rules`: `key` (постоянный идентификатор, на него ссылается история `achievement_awards`), `kind` (`award`/`record`), `subject`, `metric`, для награды `comparison` (`gte`/`lte`) и `threshold`, для рекорда `direction` (`max`/`min`), фильтры, `name`, `description` (до 160 знаков), `image_id`, `enabled`, `builtin`, `position`.

Проверка ввода — [game-rule-validation.ts](../../lib/game-rule-validation.ts) (той же схемой пользуется редактор в браузере), сохранение — `saveRules` в [game-rules.ts](../../lib/game-rules.ts): список целиком, в одной транзакции, с аудитом `gamification.rules`. Нельзя удалить встроенное правило и правило, награду которого уже кто-то получил, — их можно только выключить; нельзя превратить награду в рекорд; иллюстрация должна существовать в медиатеке.

Встроенные награды: Первый выход, Сборка до винтика, Без проводов (Di2/AXS/eTap), 10/50/100 сердец, Любимец витрины, 10/50 попутчиков, Без границ, В теме, Сотка (покатушка от 100 км), Горный козёл (от 1000 м набора), Гонщик (от 50 км/ч), Круглый год (покатушки в каждом месяце года), Летописец (10 записей журнала), Механик (10 записей об обслуживании).

Встроенные рекорды: Без компромиссов, Бюджетный герой, Легче ветра по MTB/гравию/шоссе, Тяжеловоз, Ветеран (самый старый модельный год), На максималках, Каждая деталь на месте, Марафонец, Альпинист, Черепаха (самая низкая средняя скорость на покатушке от 10 км), Наматыватель (больше всех км за 30 дней), Любимец публики, Безумная сборка, Чистая работа, Велосипед мечты, Выбор сообщества.

## Выдача и пересчёт

Награды выдаются в момент события: триггеры на велосипедах, деталях, фото, лайках, подписках, обсуждениях, покатушках и записях журнала вызывают `cola_award_user`, которая проходит по включённым наградам. Награда за велосипед остаётся за велосипедом, награда за покатушку или за человека — за человеком. Выданная награда не отзывается, даже если условие перестало выполняться.

После нового или изменённого правила администратор нажимает «Пересчитать награды» (`recalculateAwards`): пересчёт идёт пачками по 200 человек, каждая пачка — своя транзакция, результат — число выданных наград, действие пишется в аудит. Рекорды не хранятся: лидер определяется при каждом открытии страницы, при равенстве — по стабильному ID.

## Приватность

Считается только публичное: публичные велосипеды и покатушки незаблокированных владельцев, опубликованные публичные записи журнала (кроме статей). Цена — только при включённом показе, максимальная скорость — только если владелец показывает её в покатушке (`visible_metrics`), запланированная покатушка без трека не участвует. Велосипед, исключённый модератором, не держит рекорды; реакции блокированных пользователей и собственные голоса не считаются. Выключенная награда пропадает с полок, но остаётся в истории.

## Миграция

`027_game_rules.sql` переносит прежние награды и рекорды в правила с теми же ключами (история выдачи не меняется), переносит из `gamification_settings` иллюстрации (только существующие файлы), описания и выключенные рекорды, берёт порог «Сборки до винтика» из настроек оценки и выдаёт новые награды за уже сделанное. В `gamification_settings` остаются параметры рейтинга: валюта, реакции, минимальная заполненность, минимальная цена, границы веса; #176 также хранит здесь закрытый `imagePrompt`, исключённый из публичного DTO.

Новая метрика требует SQL в функции значений, строки в каталоге и тестов на приватность. Не привязывайте логику к названию: его меняет администратор.

Для локальной диагностики запросов из корня checkout с установленными devDependencies запустите `node scripts/explain-records.js` ([скрипт](../../scripts/explain-records.js)). Он применяет текущие SQL-миграции к одноразовой PGlite в памяти и создаёт синтетический набор: 500 владельцев, 2 000 велосипедов (1 800 публичных), 42 000 компонентов, 2 000 фото и 20 000 лайков. Рабочая БД и `DATABASE_URL` не используются.

Скрипт выводит `EXPLAIN (ANALYZE, BUFFERS)` для `leaderboardSQL`, затем вызывает актуальный `records(q)` для всех включённых правил и печатает число строк, рекордов, держателей и время обеих операций. Это диагностика совместимости и производительности на синтетических данных; она не измеряет production SLA и не заменяет тесты наград, покатушек и приватности. Покатушек в наборе нет, поэтому часть правил остаётся без держателя. Запускайте на машине разработчика, не в production-образе без devDependencies.

## Hall of Fame: текущий снимок (#157)

Карточка рекорда показывает действующего holder и значение, велосипед/покатушку и владельца либо участника. Над карточками показано «Актуально на …» из `records.asOf`. Это время снимка, а не дата получения рекорда: истории смены holders и `held_since` нет.

Карточка награды показывает `latestRecipient` (`author`, необязательный `bike`, `awardedAt`) и прежний `earners` — число уникальных видимых получателей. Обе части берутся одним SQL-запросом из одинаково отфильтрованных строк; последний определяется по `awarded_at DESC, id DESC`. Приватный/удалённый велосипед, заблокированный получатель и велосипед, уже не принадлежащий получателю, не раскрываются; выбирается предыдущая доступная выдача или `null`. Дата — сохранённый `awarded_at`, `<time datetime>` содержит ISO timestamp, текст отображается в часовом поясе браузера. Для наград за покатушки сохранялся только пользователь: карточка не угадывает исходную покатушку и не раскрывает её.

Плотная сетка сохраняет группы, все имена и ссылки без обрезания, обе темы, перенос длинных слов и reduced motion. Правила расчёта/выдачи и существующие полки наград не меняются.

## Закрытый гайд иллюстраций (#176)

Админка → Механики → Награды и рекорды → «Гайд для иллюстраций наград». Отдельная форма сохраняет текст до 8000 символов; пустой текст очищает гайд. Хранилище — ключ `imagePrompt` существующей `gamification_settings.value`, новая миграция не требуется. `/api/game/admin/image-prompt` доступен только действующему незаблокированному администратору; запись требует same-origin и повторно проверяет роль под блокировкой в транзакции. Аудит `gamification.image_prompt` фиксирует действие без текста.

Публичный `gameSettings()` возвращает только разрешённые параметры рейтинга. Prompt не попадает в `/api/site`, Hall of Fame, личные полки или экспорт аккаунта. Сохранение рейтинга обновляет его ключи и сохраняет prompt; сохранение prompt не меняет рейтинг, правила, выдачи и изображения. Вывод — обычный текст в textarea, без HTML/Markdown-рендеринга, внешних AI API и автоматической генерации.

Проверки #157/#176: `gamification.test.js` — порядок и приватность получателей; `game-prompt.test.js` — границы текста, права и перезапуск БД; `gamification-http.js` / `game-prompt-http.js` — реальные API, Origin, отзыв роли и сохранность наград; `gamification-layout.spec.js` / `game-prompt.spec.js` — оба размера экрана, темы, длинные имена, даты, экранирование текста и axe.
