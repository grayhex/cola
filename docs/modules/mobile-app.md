# Мобильное приложение

[Оглавление](../README.md)

## Назначение

Раздел админки «Мобильное приложение» (#338) меняет то, что Android-клиент ([grayhex/colabike-android](https://github.com/grayhex/colabike-android)) умеет показывать без новой сборки: экран запуска, знакомство, сообщение, служебные ссылки, доступность уже встроенных функций и политику версий. Приложение читает это из публичного `GET /api/v1/app-config`.

Сервер задаёт только контент и доступность. Раскладка, стили, Compose-параметры, HTML, JavaScript и код сюда не попадают. Включённый флаг не создаёт функцию, которой нет в APK. Системный Android SplashScreen и иконка остаются ресурсами APK. Секретов, ключей, токенов и подписей в настройках нет.

## Данные

`mobile_settings` хранит `value` (то, что правит администратор), `version` и две служебные редакции: `onboarding_revision` и `notice_revision`. Редакция блока — номер версии сохранения, которое последним изменило этот блок. Приложение сравнивает редакцию на равенство с той, что человек уже прошёл или закрыл, и показывает новую редакцию снова. Миграция создаёт строку с пустым `value`: всё выключено, ссылки ведут на страницы сайта.

| Блок           | Поля и лимиты                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Экран запуска  | `enabled`; `assetId` (только растр); `contentMode` `fit`/`crop`; подпись до 80; название для админки до 150 — в приложение не уходит                                                                          |
| Знакомство     | `enabled`; до 6 карточек `{ title 1–80, body ≤ 400, assetId? }`                                                                                                                                               |
| Сообщение      | `enabled`; тип `promo`/`service`/`maintenance`; заголовок до 80, текст до 500, `assetId?`; кнопка — текст до 40 и ссылка, только вместе                                                                       |
| Ссылки         | `help`, `privacy`, `terms`, `about`, `support`; пусто — умолчание: `/about#guide`, `/legal/privacy`, `/legal/terms`, `/about`; у поддержки умолчания нет                                                      |
| Внешние домены | до 20 доменов в ASCII-форме; совпадение точное (`www.rustore.ru` ≠ `rustore.ru`)                                                                                                                              |
| Функции        | ключи camelCase до 40 знаков, не больше 40 ключей вместе со встроенными; известные: `chat`, `market`, `componentCatalog`, `rides`, `bikeEditor`, `journalEditor`, `nativeYandexSignIn`, по умолчанию включены |
| Версии         | `minimumSupportedVersionCode`, `latestVersionCode` (1…2 100 000 000, минимальная не больше последней); `updateMode` `soft`/`hard`; `updateUrl`; текст до 300                                                  |

Тексты — обычный текст: разметка остаётся буквами, управляющие символы и переносы в однострочных полях отвергаются. Ссылка разрешена, только если это страница сайта (`/…`, но не `//…`) или `https`-адрес домена из списка. Логин и пароль в адресе, порт, `javascript:`, `intent:`, `data:`, схемы приложений и `http` для внешних адресов отвергаются.

Блок, который при чтении перестал проходить схему (например, после отката версии сайта), заменяется умолчаниями только сам. Остальные блоки и публичный ответ продолжают работать.

## Сохранение

`PUT /api/admin/mobile` принимает `{ value, version, confirm?, keepRevision? }` и выполняется в одной транзакции:

1. Строгая схема и правила между полями. Ошибка — 400 `invalid_settings` со списком `problems` по путям полей.
2. Строка `mobile_settings` блокируется `FOR UPDATE`; чужая версия — 409 `version_conflict`.
3. Подтверждения. Включение `hard` или повышение его минимальной версии требует `confirm.hardUpdate`, публикация сообщения `maintenance` — `confirm.maintenance`. Без подтверждения — 428 `confirmation_required` со списком `confirm`. Редактор спрашивает сам до отправки и повторяет вопрос, если сервер увидел другое.
4. Каждое назначенное изображение (в том числе выключенного блока) блокируется `FOR SHARE` в порядке UUID, тем же порядком, каким очистка медиатеки берёт `FOR UPDATE`. Удалённое — 409 `asset_missing`, SVG или Rive — 400 `asset_format`.
5. Новая версия и редакции: изменённый блок получает номер новой версии, если администратор не снял «Показать снова…» (`keepRevision`) для мелкой правки.
6. Аудит `mobile.update` с номером версии.

Назначенные изображения считаются используемыми: медиатека показывает «Мобильное приложение», удаление одного файла возвращает 409, массовая очистка пропускает их. Защита читает сырой JSON строки, поэтому не зависит от того, проходит ли значение схему.

## Публичный ответ

`GET /api/v1/app-config` одинаков для всех. Cookie и `Authorization` не читаются, поэтому недействительный токен не даёт 401. Схема `AppConfig` строгая и описана в OpenAPI:

- `revision` — версия настроек, `updatedAt` — время сохранения.
- `launch`: `enabled` и `imageUrl`. Включённый экран всегда с картинкой; у выключенного картинки и подписи нет.
- `onboarding`: `enabled`, `revision`, карточки по порядку; у выключенного — пустой список.
- `notice`: `null` или `{ revision, kind, title, body, imageUrl, action }`; `action` — `{ label, url }` или `null`.
- `links`: абсолютные адреса. Ссылки перепроверяются при каждом чтении: после смены адреса сайта сохранённая ссылка на прежний домен заменяется умолчанием.
- `features`: открытый словарь `boolean`. Известные ключи приходят всегда. `chat` бывает `true`, только если настроен Stream Chat. `nativeYandexSignIn` — только если настроены Яндекс ID и `NATIVE_AUTH_RETURN_URL`. Флаги — не граница доступа: права проверяет API.
- `compatibility`: версии, режим, адрес и текст обновления. `hard` без адреса или минимальной версии при чтении становится `soft`, чтобы не запереть людей в приложении без выхода.

Изображения — пути сайта `/api/assets/<id>` к публичным неизменяемым WebP; клиент дописывает адрес сервера и выбирает `?width=` из набора 160–2400. Новая картинка всегда получает новый адрес.

Кэш: `Cache-Control: public, max-age=60` и сильный `ETag`, вычисленный по самому ответу. Поэтому он меняется и при сохранении, и при смене настроек сервера (готовность входа через Яндекс ID, адрес сайта). Запрос с `If-None-Match` получает 304 без тела. Другие методы — 405 с `Allow: GET, HEAD, OPTIONS`.

Контракт расширяется только добавлением полей. Неизвестные поля и ключи функций клиент пропускает. Неизвестные значения перечислений трактуются как `crop`, `promo` и `soft`; генератор Kotlin-клиента сводит их к запасному значению (`enumUnknownDefaultCase`).

## Что делает клиент

Задача клиента — [colabike-android#14](https://github.com/grayhex/colabike-android/issues/14). Сервер рассчитан на такой порядок работы:

1. На старте использовать встроенные умолчания или последний сохранённый ответ.
2. В фоне обновить его условным запросом с `If-None-Match`.
3. Применять новую `revision` целиком, вместе с уже скачанными картинками.

Экран запуска и картинки грузятся только с доверенного адреса ColaBike: в ответе нет чужих адресов изображений. Ссылки клиент проверяет ещё раз своим allowlist: страницы сайта открываются во встроенной навигации, разрешённые внешние `https` — в браузере. Срок жизни сохранённого жёсткого режима после отката на сервере определяет клиент.
