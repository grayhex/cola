# Поиск и накопленный опыт

[Оглавление](../README.md)

## Назначение

Поиск соединяет публичные велосипеды, записи журнала и пользователей. Страницы опыта по модели/детали собираются из существующих публикаций, а не из заранее созданного каталога пустых страниц. Совместимость компонентов здесь — пользовательский опыт с контекстом байка, не техническая гарантия.

## Точки входа

`/search`, `/experience`, `/journal`, `/saved`; глобальное действие поиска и похожие сборки из карточки байка. HTTP поиска начинается в `/api/search`, лента — `/api/community/feed`. Режим подписок журнала объединяет подходящие записи автора **или** велосипеда без дублей.

## Данные и основные функции

[search.js](../../lib/search.js): `searchInput` ограничивает фильтры, `searchExperience` формирует выдачу. [experience-catalog.js](../../lib/experience-catalog.js) описывает назначения и варианты написания. [015_discovery.sql](../../db/015_discovery.sql) добавляет соответствующие связи и учёт.

Назначения и aliases живут в существующем версионированном `site_catalog`. Снимки деталей в журнале остаются самостоятельной исторической информацией: поиск по такой детали должен смотреть snapshot, а не сегодняшнюю комплектацию велосипеда.

## Сценарий и ограничения

Фильтры включают марку, модель, год, компонент и назначение. Нормализация учитывает регистр, пробелы/пунктуацию и ё/е; управляемые aliases связывают разные написания. Страница конкретной модели сравнивает каноническую идентичность, обычный поиск допускает фрагмент. Scope alias для модели — марка, для детали — категория; циклы и конфликтующие правила запрещены.

Отключённое назначение не предлагается новым байкам, но сохраняется у существующих. Объединение справочного дубля не переписывает авторский текст и journal snapshots. Свободный ввод марок/деталей остаётся допустимым.

Сохранённое — личный список. Подписки и сохранения доступны читателю без своего байка. Каждое чтение заново проверяет публикацию, велосипед и блокировку автора; скрытое не должно попадать в total, похожие сборки и детали. Отписаться/убрать сохранение можно и после скрытия цели.

Учёт участия минимален: дневные действия и псевдонимный ключ для возвратов; служебная связь с аккаунтом нужна для каскадного удаления. Это **не анонимная аналитика**. Ключ не выдаётся клиенту; агрегаты видны администратору. Не расширяйте этот контур незаметно до хранения текста, IP или истории маршрутов.

## Расширение и проверки

Выдача использует ограниченные параметры, SQL-пагинацию и bulk DTO. Count и список могут читаться отдельными statements. Нормализация строк/JSON пока вычисляется в SQL; при росте нужен профилинг, а не кэш всех приватных текстов.

Проверки: [discovery.test.js](../../tests/discovery.test.js), [discovery-http.js](../../tests/discovery-http.js), [discovery.spec.js](../../tests/e2e/discovery.spec.js). Обязательны обе подписки без дублей, пользователь без велосипеда, скрытие в total, aliases, самосбор, устаревшая деталь в snapshot и отметка решения только автором вопроса.
