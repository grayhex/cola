# Сообщения: Stream Chat (#170)

Чат — отдельный провайдер данных. ColaBike проверяет свою сессию, подтверждение почты и участников; Stream хранит и доставляет переписку. В PostgreSQL нет копии сообщений: миграция `031_chat_lifecycle` добавляет только зарегистрированные идентификаторы и очередь синхронизации/удаления.

## Реализованный этап

`/messages`: личные диалоги, группы из 3–8 человек, список переписок, непрочитанное, typing/read events, ответы в ветке, реакции, жалоба через меню сообщения, изображения JPEG/PNG/WebP до 5 МиБ. Интерфейс позволяет прикрепить до четырёх изображений за раз; ограничения формата и размера также задаются на стороне Stream. Состав созданной группы в этом этапе не редактируется. Создание диалога с собой, неподтверждённым или заблокированным аккаунтом отклоняется сервером.

В шапке есть «Сообщения» и счётчик, в чужом публичном профиле — «Написать». SDK и WebSocket загружаются только на странице переписки; на остальных страницах счётчик обновляется по HTTP раз в минуту, при навигации и возврате на вкладку. Светлая/тёмная темы следуют общему переключателю; на телефоне список и переписка показываются по очереди. Нет audio/video, push, поиска по всей переписке, собственного WebSocket-сервера или Android-клиента.

## Интерфейс сообщений (#217)

«Новое сообщение» открывает общий доступный диалог ColaBike: фокус в поиске, Escape закрывает окно и возвращает фокус. Поиск принимает имя или `@username`, отменяет устаревшие запросы и различает загрузку, пустой результат и ошибку с повтором. До ввода показывает до 20 подтверждённых незаблокированных пользователей, **на которых подписан сам зритель**; глобального каталога или случайных рекомендаций нет. Ответ `/api/chat/people` содержит только `id/name/username/avatar_id` и `mode`. Один выбранный человек создаёт DM, несколько — группу с обязательным названием; сервер повторно проверяет доступность всех участников.

Список диалогов показывает аватар, имя, превью последнего сообщения, время, непрочитанное и активное состояние. Обновления сообщений и read state получает штатный `ChannelListItem` SDK, а ColaBike задаёт его внешний вид. В заголовке переписки доступны участники и информация; composer, ветки, цитаты, редактирование, реакции, typing и отправка изображений используют существующий SDK и разрешённые действия. Палитра, шрифт и поверхности берутся из токенов сайта, без изменения vendor grants или transport.

Выбранный диалог имеет адрес `/messages?channel=colabike%3A…`: перезагрузка и история браузера восстанавливают экран, но сам CID не даёт доступа — Stream проверяет membership, а UI дополнительно проверяет текущего участника. Ссылка из профиля `?to=UUID` продолжает создавать/открывать идемпотентный DM. На телефоне кнопка «К списку диалогов» открывает список; черновик composer сохраняется в памяти SDK при переключении экранов, без записи текста в localStorage. Экспорт остаётся внизу списка.

Регрессии: поиск и подсказки на настоящем SQL с фильтрацией self/blocked/unverified и экранированием wildcard; HTTP auth и email-policy; браузерные сценарии пустого списка, поиска/ошибки/повтора, выбора клавиатурой, DM/groups, истории и черновика, двух сессий с доставкой/read events. Скриншоты `chat-*.png` сохраняются в CI для обеих тем и desktop/mobile. Изолированный провайдер не заменяет оставшуюся live-приёмку #170.

## Совместимость и стоимость

Проверено 27.09.2026 по текущим пакетам и официальной документации: `stream-chat@9.53.0`, `stream-chat-react@14.12.0`, Node 24, React 19.3, Next 16.3. React SDK 14 использует `MessageComposer`; подключение находится в ленивом client component, серверный SDK — external dependency standalone-сборки. postinstall обоих пакетов устанавливает contributor Husky hooks, поэтому отключён через `allowBuilds: false`; опубликованные пакеты уже собраны.

Публичный [прайс](https://getstream.io/chat/pricing/) на дату проверки показывает Build: 1000 MAU / 100 одновременных соединений, Start: 10 000 MAU / 500 соединений, $499 при месячной оплате или $399/месяц при годовой. Это не подтверждает тариф проекта владельца. До включения сверьте в Dashboard MAU, concurrent connections, storage, bandwidth, rate limits, платные функции и billing alerts. Наличие бесплатной программы Maker само по себе не означает её одобрение. Подключение SDK только на странице сообщений ограничивает лишние соединения и MAU.

Официальный [Android SDK](https://getstream.io/chat/docs/sdk/android/) может использовать те же Stream IDs, каналы и серверный token provider. Будущему native-клиенту нужен отдельно спроектированный ColaBike login/token exchange; браузерный cookie + Origin контракт не является готовой Android-авторизацией. Secret в APK не передаётся.

## Настройка владельцем

Регион **EU West** согласован владельцем в #170. Наличие нужного региона, тарифа, DPA и параметров конкретного проекта проверяется в Dashboard: код этого не доказывает. Используйте отдельное Stream-приложение только для ColaBike: настройка upload/auth policy действует на всё приложение.

В `.env.production` (не в Git, build args или публичных настройках админки):

```dotenv
STREAM_CHAT_ENABLED=false
STREAM_CHAT_API_KEY=<public API key>
STREAM_CHAT_API_SECRET=<server secret>
```

Ключ передаётся браузеру при выдаче токена из runtime-конфигурации; повторная сборка для смены ключа не нужна. `NEXT_PUBLIC_STREAM_CHAT_API_KEY` поддерживается как fallback при ручном запуске Node; Compose использует `STREAM_CHAT_API_KEY`. App ID не нужен API-клиенту. Отсутствие любого ключа или `STREAM_CHAT_ENABLED=true` скрывает чат и даёт безопасную заглушку; запуск сайта не блокируется.

Команды ниже предназначены для оператора после приёмки PR. Не запускайте `--apply` для приложения, которым пользуется другой продукт:

```sh
# Только проверка, без изменения Stream.
docker compose --env-file .env.production -f compose.prod.yaml run --rm --no-deps migrate node scripts/chat-setup.js

# Явное применение ролей, типа канала и ограничений вложений.
docker compose --env-file .env.production -f compose.prod.yaml run --rm --no-deps migrate node scripts/chat-setup.js --apply
```

Если предыдущий `--apply` остановился на настройке вложений, после обновления кода повторите его и затем запустите проверку без `--apply`: Stream принимает расширения файлов только с ведущей точкой (`.jpg`, `.jpeg`, `.png`, `.webp`).

Скрипт создаёт `colabike_user`, `colabike_member`, канал типа `colabike`; выдаёт участнику только необходимые права. Обычные user/guest/anonymous/channel_member не получают доступ к этому типу. Пользователь не может создавать каналы напрямую, добавлять участников, менять роль/профиль или искать весь каталог пользователей Stream. Создание участников и каналов идёт через ColaBike. Проверка auth/permissions, grants и upload policy перед выдачей токена/канала закрывает доступ при несовместимой настройке; результат кешируется на 30 секунд.

После проверки политики, privacy/retention и сценария приёмки включите флаг и пересоздайте `app` и `chat-sync` обычным процессом деплоя. CSP разрешает только Stream chat API/WS и его CDN; произвольные URL провайдера или тестовый обход в production не предусмотрены.

## Контракт и безопасность

| Endpoint                      | Назначение                                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `POST /api/chat/token`, `{}`  | Токен только текущего подтверждённого пользователя, TTL 300 секунд, `Cache-Control: no-store`                      |
| `POST /api/chat/channels`     | `{kind:"dm",members:[uuid]}` или `{kind:"group",name,members:[uuid,…]}`; текущий пользователь добавляется сервером |
| `GET /api/chat/people?q=…`    | До 20 подтверждённых незаблокированных пользователей; поиск от двух символов; без запроса — собственные подписки   |
| `GET /api/chat/unread`        | Число непрочитанных текущего пользователя; без подключения браузерного SDK                                         |
| `POST /api/chat/export`, `{}` | JSON своих данных, сообщений и реакций из Stream                                                                   |

POST проверяет Origin, все маршруты — сессию и email, действуют ограничения частоты и размера тела. При выдаче токена/создании канала пользователь и действующая сессия повторно проверяются под SQL-блокировками. `user_id` не принимается в token body. Stream ID — `cola_` + UUID без дефисов; он не меняется с именем/username. Передаются только ID, имя, роль и публичный URL аватара, без email, сессии, биографии и приватного гаража. JWT хранится SDK в памяти, secret остаётся серверным. Ошибки провайдера не сериализуются и не логируются с headers/body/token.

Сообщения отображаются как текст с HTTP(S)-ссылками (`noopener noreferrer nofollow`), без произвольного HTML, автозагрузки link previews или внешних картинок. Вложения отображаются только как изображения с CDN Stream; запрещены SVG, документы, audio/video. Обработку жалоб выполняет администратор в Stream Dashboard; жалоба не означает автоматическую блокировку. Выбранные платные правила automod требуют отдельной настройки владельцем.

## Блокировка, выход и удаление

SQL-триггеры ставят задания при смене имени/аватара/блокировки, удалении аккаунта и удалении сессии (logout, отзыв устройства, смена пароля, действия администратора). `chat-sync` из образа `ops` опрашивает очередь каждые 5 секунд. Он синхронизирует профиль, отзывает старые токены и деактивирует пользователя для закрытия уже открытых соединений. Незаблокированный аккаунт затем реактивируется; свежий токен доступен только с действующей ColaBike-сессией. Отзыв одной ColaBike-сессии отзывает старые Stream-токены **всех устройств** этого пользователя; оставшиеся действующие сессии могут получить новые.

Удаление оставляет durable-задание без FK на удалённого пользователя: revoke, deactivate, hard delete пользователя/его сообщений и DM conversation channels. Удаление DM затрагивает историю обоих участников. Асинхронная задача отслеживается до завершения; ошибка возобновляет попытки. Остальные участники групп не удаляются. Очередь не содержит переписки, email или копий вложений. Задание удаления создаётся и для аккаунта без локальной chat identity: оно убирает возможный remote upsert после отката SQL-транзакции; если пользователя в Stream нет, задание просто завершается. Без настроенных credentials эти UUID-задания остаются до настройки worker.

Отзыв у провайдера асинхронный: обычная задержка — интервал worker и время API, при outage — до восстановления Stream и следующей попытки (backoff до 5 минут). TTL ограничивает повторное использование токена, но не является гарантией немедленного закрытия уже открытого WebSocket. До завершения deactivation удалённый доступ может сохраняться. Это ограничение должно пройти приёмку владельцем; для немедленного ограничения при аварии нужны действия оператора в Stream.

Флаг off закрывает новые входы в чат через ColaBike, но сам по себе не отзывает ранее выданные токены и открытые Stream-соединения. Для аварийного полного отзыва нужен операторский revoke/deactivate в Stream.

При `STREAM_CHAT_ENABLED=false` worker продолжает обрабатывать старые задания, если сохранены credentials. Не удаляйте секрет и не останавливайте worker до опустошения очереди. Проверяйте состояние `chat-sync`, события `chat_sync_retry`/`chat_sync_unavailable` и возраст очереди:

```sql
SELECT kind, count(*), min(updated_at) AS oldest,
       max(attempts) AS attempts FROM chat_jobs GROUP BY kind;
```

Повторные ошибки/растущий возраст >5 минут требуют проверки доступности, ключей, роли и vendor deletion task. `node scripts/chat-sync.js --once` выполняет одну партию с теми же настройками. Backup/restore останавливает также `chat-sync`: восстановленная очередь не должна неожиданно отправлять изменения в Stream до проверки оператором.

## Privacy, retention и переносимость

Stream получает текст, вложения и служебные события переписки, публичные имена/аватары, стабильные псевдонимные ID и сетевые данные подключения. EU West означает внешнего обработчика; это не локальное хранение в PostgreSQL и не end-to-end encryption. Перед включением владелец проверяет [DPA](https://getstream.io/legal/dpa/), subprocessors/передачу данных и отражает Stream, цели, регион, сроки хранения, жалобы, экспорт и удаление в действующей политике приватности сайта. PR не публикует новую редакцию юридического документа вместо владельца.

Срок хранения не выдумывается и автоматически не применяется. Оператор согласует срок и устанавливает [retention policy](https://getstream.io/chat/docs/node/data-retention-policy/) в Dashboard/API; доступность и квоты сверяет с тарифом. Очистка асинхронна, поэтому нельзя обещать удаление в точную секунду. Проверяйте отдельно срок CDN-ссылок, удаление объектов вложений и резервные копии провайдера: hard-delete API и исчезновение сообщения из UI не доказывают немедленное исчезновение всех копий файла.

Кнопка «Скачать мои сообщения» экспортирует данные конкретного пользователя через `exportUser`. Это отдельный файл от общего ColaBike account export; ссылка есть в настройках аккаунта. PostgreSQL backup сохраняет identity/outbox, **не сообщения и вложения Stream**. Для полного аварийного переноса нужен операторский экспорт каналов/сообщений и медиа через Stream API/dashboard с проверкой полноты, прав участников и TTL ссылок.

Vendor lock-in: формат каналов, IDs сообщений/реакций, read state и SDK принадлежат Stream. При миграции сохраняйте соответствие `cola_` ↔ UUID, экспортируйте данные до прекращения договора, конвертируйте membership/threads/attachments и проверьте replay/дедупликацию. Автоматический импорт в другой сервис в этот этап не входит.

## Приёмка и границы тестов

CI не получает реальные Stream secrets. Unit/PGlite проверяет подпись/TTL JWT, роли, участников и durable lifecycle на настоящих SQL-триггерах. Отдельный HTTP-прогон использует реальный Next, БД и test-only Node preload провайдера; он проверяет собственный токен, CSRF, блокировку/выход, export и безопасную ошибку. Браузерный fixture проверяет реальный React/JS SDK через подменённые REST/WS ответы, две сессии, DM delivery, read events, мобильный список и темы. Это **не live smoke** и не доказательство конфигурации Stream.

Владелец проверяет в отдельном Stream-приложении и затем в согласованном production-окне:

1. Два подтверждённых ColaBike-пользователя: «Написать» из профиля → обмен сообщениями, typing/read receipts, реакция, ответ в ветке; обновление страницы и восстановление сети без дублей. Проверить refresh токена после 5 минут.
2. Добавить третьего пользователя в новую группу; посторонний не читает её даже по известному CID. Токеном клиента напрямую нельзя создать канал, добавить участника, изменить роль или получить каталог Stream-пользователей.
3. Изображение до 5 МиБ проходит; oversized/SVG/документ отклоняется и при прямом SDK-запросе. HTTP(S)-ссылка безопасно открывается, произвольный HTML/внешний tracking pixel не исполняется. CSP проверяется в `enforce`.
4. Жалоба доходит до Dashboard и видна оператору. Просмотреть ограничения тарифа и уведомления расходов.
5. Сменить имя/аватар, отозвать сессию, заблокировать активного собеседника. Проверить уже открытый WS и повторный запрос токена; после разблокировки доступ возвращается только с действующим входом.
6. Экспортировать данные, удалить тестовый аккаунт, дождаться пустой очереди и завершения vendor task; проверить удаление пользователя, сообщений/DM и политику вложений. Отключить Stream на время — задание сохраняется и выполняется после восстановления.
7. Desktop Chromium и mobile Safari/WebKit, обе темы, клавиатура, узкий экран; флаг off/отсутствующие ключи не ломают главную, профиль и вход.
