# Синхронизация покатушек

[Оглавление](../README.md) · [Покатушки](../modules/rides.md)

## Ride with GPS

В `/account?tab=rides` пользователь подключает Ride with GPS через OAuth. Первая синхронизация получает историю за последние 12 календарных месяцев, затем подписанные уведомления инициируют получение изменений через официальный sync API. Импортируются только собственные `trip` с `activity_type`, начинающимся на `cycling:`. Routes, чужие pinned trips, `e_biking:*`, бег и другие виды пропускаются. Стационарные велотренировки сохраняются без карты с доступными числовыми метриками.

Пользователь может выбрать велосипед для импорта. Без явного выбора назначается единственный текущий велосипед либо единственное совпадение типа road/gravel/MTB/commute. Если совпадение неоднозначно или велосипед отсутствует, активность ждёт выбора в кабинете; выбор велосипеда и «Синхронизировать сейчас» повторяют обработку. Бывший велосипед не назначается новым поездкам.

Новые поездки получают текущий default ColaBike: непубличные, обрезание краёв выключено, радиус из настроек покатушек, базовый набор видимых метрик. FIT проходит `parseTrack` и те же правила геометрии/скорости/датчиков. Если экспорт FIT не поддержан (404/406/422), запрашивается TCX. Ошибка сети/авторизации не переключает транспорт на неофициальные endpoints. Числовые дополнительные метрики из API дополняют данные парсера. Пульс и мощность не публикуются без выбора владельца.

Обновление в источнике заменяет трек и метрики, сохраняя велосипед, описание, публичность, privacy и видимые показатели ColaBike. Название обновляется, только если пользователь не поменял его здесь. Удаление в RWGPS **удаляет связанную импортированную поездку ColaBike** согласно решению #226. Ручная поездка с совпадающим файлом не присваивается интеграцией: импорт помечается дубликатом, remote delete её не затрагивает. Локально удалённая поездка не восстанавливается повторной доставкой. Отключение сохраняет ранее импортированные поездки.

## Настройка оператором

1. В [настройках API-клиента RWGPS](https://ridewithgps.com/api/api_clients) создать клиент. Redirect URI для production: `https://colabike.ru/api/activity-sync/rwgps/callback` (для другого домена используется его `APP_ORIGIN`).
2. Webhook URL: `https://colabike.ru/api/activity-sync/rwgps/webhook`. Включить тип `trip` в настройках клиента. RWGPS подписывает тело HMAC-SHA256 с client secret; приложение проверяет также API key.
3. В серверном окружении задать `RWGPS_API_KEY`, `RWGPS_CLIENT_ID`, `RWGPS_CLIENT_SECRET`, `ACTIVITY_TOKEN_KEY` (64 hex-символа из `openssl rand -hex 32`), затем `RWGPS_ENABLED=true`. Не использовать `NEXT_PUBLIC_*`, не помещать ключи в Git или issue. Сохранить encryption key отдельно от БД: без него восстановленные credentials не читаются; при его утрате потребуется переподключение.
4. Применить миграцию `034_activity_sync` обычным migrate, поднять app и `activity-sync`. Compose использует уже собранный ops-образ, приватный volume rides и непривилегированного пользователя. Нового брокера/БД не требуется. На host запуск worker: `node scripts/activity-sync.js`; одноразовый проход: `node scripts/activity-sync.js --once`.
5. Проверить OAuth настоящим аккаунтом, собственную новую велопоездку, повтор sync, изменение/удаление в RWGPS и отключение. Offline CI не заменяет проверку зарегистрированного клиента и доставки webhook из интернета.

Без настройки кнопка недоступна, ручной GPX/FIT/TCX и Garmin CSV продолжают работать. Конфигурация `RWGPS_ENABLED=false` прекращает сетевую обработку, сохраняя задания. Перед постоянным отключением сначала отключить пользовательские связи и дождаться опустошения revocation outbox. Не удалять encryption key, пока остаются credentials/outbox.

## Доставка и данные

- `activity_connections`: владелец, provider, внешний user ID, generation, зашифрованный токен AES-256-GCM, велосипед, граница истории и cursor. OAuth state одноразовый, с TTL 10 минут, связан с пользователем и текущей сессией. Начало OAuth требует same-Origin POST. Callback не принимает секретов от браузера кроме одноразового кода.
- `external_activities`: provider + внешний аккаунт + trip ID отдельно от пользовательского названия, ссылка на поездку, ограниченные метаданные и состояние. Эти данные не входят в публичный DTO. Внешняя идентичность сохраняется при reconnect и удалении поездки, чтобы не создавать её повторно.
- `activity_jobs`: durable очередь sync/upsert/deleted; webhook только проверяет подпись и делает один SQL enqueue перед HTTP 200. Никаких скачиваний в запросе webhook. Входные `item_url`/`next_sync_url` не используются: HTTPS endpoint конструируется из проверенного ID, redirects с токеном запрещены.
- Worker получает изменения после сохранённого `meta.rwgps_datetime`, атомарно ставит отдельные activity jobs и продвигает cursor. Поэтому ошибка одного FIT не теряет остальные активности. Повторы с backoff до часа; ручная синхронизация ускоряет retry, включая ожидание велосипеда. Лимиты файлов/точек/числа поездок и бюджет импорта применяются на сервере.
- Revision задания и generation подключения перепроверяются после сети под блокировкой владельца. PostgreSQL advisory lock сериализует worker-процессы; доменные транзакции также защищают повторную обработку. После disconnect или удаления аккаунта запоздалый ответ не может сохранить поездку.
- `activity_revocations`: отключение сразу удаляет локальное подключение/задания; зашифрованный токен остаётся только для отзыва через `/oauth/revoke.json`, затем удаляется. Trigger создаёт outbox также при удалении аккаунта. Пока RWGPS недоступен, отзыв повторяется; локальный импорт уже остановлен. В outbox нет FK к удалённому пользователю.

RWGPS не повторяет потерянные webhooks. Следующий webhook или «Синхронизировать сейчас» восстанавливает пропущенные изменения по cursor; постоянного опроса API нет. Поддержка обновлений ограничена 50 000 событиями/8 MiB на sync-ответ: превышение даёт повторяемую ошибку без продвижения cursor. Окно истории ограничивает новые импорты; уже связанные поездки сохраняются и обновляются при повторном подключении спустя год. Импорт более старой истории доступен вручную. Неизменившийся снимок поездки не переписывает оригинал и не расходует бюджет импорта повторно.

Новые версии оригинала сохраняются под отдельным UUID; транзакция меняет `rides.track_file_id`, старый файл удаляется через существующий GC. При rollback старый оригинал остаётся целым, сироты убираются после grace period. Backup/restore останавливает worker вместе с приложением и сохраняет весь rides volume; encryption key обслуживается отдельно от архива данных.

Диагностика в кабинете: последняя полностью завершённая синхронизация, число заданий, ожидания велосипеда/ошибки. Worker пишет только тип сбоя, без tokens, payload, координат и пользовательских IDs. SQL для оператора: `SELECT count(*), min(next_attempt_at) FROM activity_jobs;` и аналогично для `activity_revocations`; не выводить колонку credentials.

## Контракт и проверки

Контракт проверен 28.09.2026: [OAuth](https://ridewithgps.com/api/v1/doc/getting_started/authentication), [webhooks](https://ridewithgps.com/api/v1/doc/getting_started/webhooks), [официальная OpenAPI-схема](https://ridewithgps.com/api/v1/openapi.yaml), [типы активностей](https://ridewithgps.com/api/v1/doc/reference/activity_types). API использует Bearer token; refresh flow не документирован. При 401 пользователь отключает и подключает аккаунт заново. OAuth client настраивается владельцем сервиса; live-приёмка требует его реальных credentials.

`tests/activity-sync.test.js` проверяет подпись, шифрование, owner/session state, FIT, метрики/privacy, retry, удаление и гонку disconnect. HTTP harness использует отдельный vendor preload в tests; приложение не имеет тестовых endpoints. Реальная конкуренция PostgreSQL — `activity-sync-concurrency.js`; оба браузера/темы — `e2e/activity-sync.spec.js`. Fixtures синтетические по официальной схеме; реальные приватные поездки и токены не включаются в Git.

Garmin #225 остаётся заблокирован внешним доступом. Общие таблицы подключения/идентичности предназначены для следующего provider, но Garmin endpoints и синхронизация пока не реализованы.
