# Безопасность и приватность

[Оглавление](../README.md)

## Что защищает приложение

[auth.js](../../lib/auth.js) создаёт случайный session token, хранит его SHA-256 digest и выдаёт `cola_session` с HttpOnly, SameSite=Lax и настраиваемым Secure. Пользователь и его текущая блокировка/роль читаются из базы. Пароли хешируются scrypt в [password.js](../../lib/password.js); неизвестный email не должен превращать вход в быстрый обход проверки. Регистрация не назначает admin.

Мутации проверяют Origin относительно `APP_ORIGIN`, пользовательские операции — владельца, административные — роль. Ограничения частоты находятся и в приложении, и в production nginx. Наличие доступа к админке не делает пользовательские API универсальным просмотром чужих приватных данных.

## Публичные границы

DTO собираются явно; не возвращайте `SELECT *` наружу с удалением нескольких известных секретов. Для поездки, записи журнала, обсуждения, ленты, поиска и уведомления проверяется текущая доступность базового объекта. Приватный велосипед закрывает связанную публичную выдачу. Сохранение ссылки и подписка не дают дополнительного разрешения.

Публичность цены — отдельная настройка. Нельзя использовать скрытую цену в публичном рекорде или вернуть её через снимок детали. Для GPX клиент получает уже разрешённую геометрию; renderer не восстанавливает разрывы и скрытые начало/конец. Полные метрики поездки могут сохраняться при урезанной публичной геометрии — это нужно объяснять пользователю.

Защищённые фото, аватары и journal media выдаются через свои API, а не статический каталог nginx. Перепроверка доступа не отзывает байты, которые посетитель успел скачать раньше.

### Медиа и кеширование

[media-cache.js](../../lib/media-cache.js) обслуживает фото велосипедов, аватары, изображения журнала и рынка. Допустимые размеры — закрытый набор `?width=160|320|640|1280` (аватары — до 320); остальные значения дают 400. Производный размер строится sharp один раз и хранится в `MEDIA_CACHE_DIR` (по умолчанию `/tmp/colabike-media-cache` внутри контейнера, не в томе `photos` и не в backup). Объём ограничен `MEDIA_CACHE_MAX_MB` (1024): при превышении удаляются самые старые файлы. После пересоздания контейнера кеш наполняется заново.

Пользовательские медиа отдаются с `ETag` и `Cache-Control: private, no-cache`. Браузер хранит байты, но при каждом показе переспрашивает сервер; сервер **сначала проверяет доступ** и только затем отвечает `304` без тела. Поэтому скрытие велосипеда, записи или блокировка автора действуют сразу: повторный запрос получает 404. ID медиа никогда не переиспользуется для других байтов, поэтому ETag — это ID, размер и версия конвейера. Графика сайта (`/api/assets/:id`) публична и неизменна по ID: `public, max-age=31536000, immutable`.

## Файлы и внешние страницы

Изображения проходят ограничения размера и декодирование/нормализацию. Обычные фото и точный lossless-путь UI-иконок — разные обработчики. Пути файлов формируются сервером; имя из ZIP/загрузки не становится путём записи. Нельзя включать SVG-исполнение ради удобства импорта.

Resolver применяет публичные адреса, проверку DNS/IP, pinning, проверку редиректов, allowlist официальных адаптеров и blocklist ручных источников. HTML/JSON извлекаются как данные, не исполняются. Ручная ссылка пользователя не освобождает от SSRF-защиты. Ошибка 403/challenge не является разрешением обходить защиту источника.

## Секреты и настройки

`DATABASE_URL`, `POSTGRES_PASSWORD`, `BIKE_RESOLVER_TOKEN`, `TRUSTED_PROXY_KEY` — серверные значения. Публичный ключ карт, наоборот, виден браузеру и ограничивается у провайдера. Не помещайте OAuth secret или внутренний адрес в публичные site settings.

Логи и трекер ошибок получают тип, код, очищенное сообщение и кадры стека, но не SQL, заголовки, cookies и тела запросов; email, IP, UUID и токены заменяются заполнителями ([мониторинг](../operations/monitoring.md#журнал-ошибок-и-трекер)). `ERROR_TRACKER_DSN` — серверная настройка: браузер отправляет свои ошибки только в `/api/client-errors`.

Приватный proxy key позволяет доверять `X-Cola-Client-IP` только от настроенного nginx. Произвольный `X-Forwarded-For` не должен менять rate-limit identity. Не включайте real-IP доверие ко всем адресам. Не публикуйте `docker compose config` с раскрытыми значениями, целый nginx-конфиг или auth headers в PR.

## Граница доверия CI и deploy

CI и production deploy выполняются на GitHub-hosted runners. Deploy-job получает SSH-секреты из environment `production` и передаёт проверенный SHA пользователю `deploy` на VPS. Ключ ограничен forced-command [ops/deploy-cola-ssh](../../ops/deploy-cola-ssh), который принимает только полный SHA и вызывает root-owned [ops/deploy-cola](../../ops/deploy-cola) через sudo. Пользователю `deploy` не нужен доступ к Docker group. **Это ограничение интерфейса, а не sandbox для недоверенного кода.** Wrapper не проверяет CI криптографически: происхождение проверенного SHA обеспечивается workflow, а production wrapper дополнительно сравнивает его с текущим `origin/main`. Установка ключа и ограничения — в [runbook](../operations/deployment.md#ssh-доступ-для-github-actions).

Код из `main`, workflow, Dockerfile, миграции, env и серверный checkout должны считаться привилегированными. CI для PR не должен получать production-секреты. Не доверяйте collaborator только на основании того, что ему предложено «не пушить в main»; правила ветки, review и ограничение environment `production` веткой `main` настраиваются в GitHub отдельно. Наличие workflow в репозитории не доказывает, что эти административные ограничения уже применены.

Официальная справка: [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use).

## Известные ограничения

OAuth не реализован. Восстановление пароля и подтверждение почты работают только при настроенном SMTP; без него владелец сервера сбрасывает пароль через CLI ([аккаунт](../modules/accounts.md#восстановление-пароля-и-подтверждение-почты)). Подтверждение почты пока не ограничивает функции сайта. CSP ограничивает framing/base/object, но не является полной allowlist для script-src. Квота одного пользователя не ограничивает общий размер сайта. Файлы и БД требуют backup и cleanup. Проверки fixture не доказывают доступность внешнего сайта или абсолютную безопасность. Подключение новых провайдеров, публикация репозитория и открытая регистрация требуют отдельной оценки данных и доступа.
