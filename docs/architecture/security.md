# Безопасность и приватность

[Оглавление](../README.md)

## Что защищает приложение

[auth.js](../../lib/auth.js) создаёт случайный session token, хранит его SHA-256 digest и выдаёт `cola_session` с HttpOnly, SameSite=Lax и настраиваемым Secure. Пользователь и его текущая блокировка/роль читаются из базы. Пароли хешируются scrypt в [password.js](../../lib/password.js); неизвестный email не должен превращать вход в быстрый обход проверки. Регистрация не назначает admin.

Мутации проверяют Origin относительно `APP_ORIGIN`, пользовательские операции — владельца, административные — роль. Ограничения частоты находятся и в приложении, и в production nginx. Наличие доступа к админке не делает пользовательские API универсальным просмотром чужих приватных данных.

## Публичные границы

DTO собираются явно; не возвращайте `SELECT *` наружу с удалением нескольких известных секретов. Для поездки, записи журнала, обсуждения, ленты, поиска и уведомления проверяется текущая доступность базового объекта. Приватный велосипед закрывает связанную публичную выдачу. Сохранение ссылки и подписка не дают дополнительного разрешения.

Публичность цены — отдельная настройка. Нельзя использовать скрытую цену в публичном рекорде или вернуть её через снимок детали. Для GPX клиент получает уже разрешённую геометрию; renderer не восстанавливает разрывы и скрытые начало/конец. Полные метрики поездки могут сохраняться при урезанной публичной геометрии — это нужно объяснять пользователю.

Защищённые фото, аватары и journal media выдаются через свои API, а не статический каталог nginx. Перепроверка доступа не отзывает байты, которые посетитель успел скачать раньше.

### Медиа и кеширование

[media-cache.js](../../lib/media-cache.js) обслуживает фото велосипедов, аватары, изображения журнала и рынка. Допустимые размеры — закрытый набор `?width=160|320|640|1280` (аватары — до 320); остальные значения дают 400. Производный размер строится sharp один раз и хранится в `MEDIA_CACHE_DIR` (по умолчанию `/tmp/colabike-media-cache` внутри контейнера, не в томе `photos` и не в backup). Объём ограничен `MEDIA_CACHE_MAX_MB` (1024): при превышении удаляются самые старые файлы. После пересоздания контейнера кеш наполняется заново.

Пользовательские медиа отдаются с `ETag` и `Cache-Control: private, no-cache`. Браузер хранит байты, но при каждом показе переспрашивает сервер; сервер **сначала проверяет доступ** и только затем отвечает `304` без тела. Поэтому скрытие велосипеда, записи или блокировка автора действуют сразу: повторный запрос получает 404. ID медиа никогда не переиспользуется для других байтов, поэтому ETag — это ID, размер и версия конвейера. Графика сайта (`/api/assets/:id`) публична и неизменна по ID: `public, max-age=31536000, immutable`.

## Файлы и внешние страницы

Изображения проходят ограничения размера и декодирование/нормализацию. Обычные фото и точный lossless-путь UI-иконок — разные обработчики. Пути файлов формируются сервером; имя из ZIP/загрузки не становится путём записи. Нельзя включать SVG-исполнение ради удобства импорта.

Resolver применяет публичные адреса, проверку DNS/IP, pinning, проверку редиректов, allowlist официальных адаптеров и blocklist ручных источников. HTML/JSON извлекаются как данные, не исполняются. Ручная ссылка пользователя не освобождает от SSRF-защиты. Ошибка 403/challenge не является разрешением обходить защиту источника.

## Секреты и настройки

`DATABASE_URL`, `POSTGRES_PASSWORD`, `BIKE_RESOLVER_TOKEN`, `TRUSTED_PROXY_KEY` — серверные значения. Публичный ключ карт, наоборот, виден браузеру и ограничивается у провайдера. Не помещайте OAuth secret или внутренний адрес в публичные site settings.

Логи и трекер ошибок получают тип, код, очищенное сообщение и кадры стека, но не SQL, заголовки, cookies и тела запросов; email, IP, UUID и токены заменяются заполнителями ([мониторинг](../operations/monitoring.md#журнал-ошибок-и-трекер)). `ERROR_TRACKER_DSN` — серверная настройка: браузер отправляет свои ошибки только в `/api/client-errors`.

Приватный proxy key позволяет доверять `X-Cola-Client-IP` только от настроенного nginx. Произвольный `X-Forwarded-For` не должен менять rate-limit identity. Не включайте real-IP доверие ко всем адресам. Не публикуйте `docker compose config` с раскрытыми значениями, целый nginx-конфиг или auth headers в PR.

## Граница доверия CI и deploy

CI и production deploy выполняются на GitHub-hosted runners. Deploy-job получает SSH-секреты из environment `production` и передаёт проверенный SHA пользователю `deploy` на VPS. Ключ ограничен forced-command [ops/deploy-cola-ssh](../../ops/deploy-cola-ssh), который принимает только полный SHA и вызывает root-owned [ops/deploy-cola](../../ops/deploy-cola) через sudo. Пользователю `deploy` не нужен доступ к Docker group. **Это ограничение интерфейса, а не sandbox для недоверенного кода.** Wrapper не проверяет CI криптографически: происхождение проверенного SHA обеспечивается workflow, а production wrapper дополнительно сравнивает его с текущим `origin/main`. Установка ключа и ограничения — в [runbook](../operations/deployment.md#ssh-доступ-для-github-actions).

Код из `main`, workflow, Dockerfile, миграции, env и серверный checkout должны считаться привилегированными. CI для PR не должен получать production-секреты. Не доверяйте collaborator только на основании того, что ему предложено «не пушить в main»; правила ветки, review и ограничение environment `production` веткой `main` настраиваются в GitHub отдельно. Наличие workflow в репозитории не доказывает, что эти административные ограничения уже применены.

Официальная справка: [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use).

## Известные ограничения

OAuth не реализован. Восстановление пароля и подтверждение почты работают только при настроенном SMTP; без него владелец сервера сбрасывает пароль через CLI ([аккаунт](../modules/accounts.md#восстановление-пароля-и-подтверждение-почты)). Публикации, комментарии и контакты продавцов требуют подтверждённой почты; единая [email-policy](../modules/accounts.md#политика-подтверждённой-почты-139) не зависит от доступности SMTP. CSP по умолчанию собирает Report-Only, сохраняя блокировку framing/base/object; enforcement включается оператором после приёмки (ниже). Квота одного пользователя не ограничивает общий размер сайта. Файлы и БД требуют backup и cleanup. Проверки fixture не доказывают доступность внешнего сайта или абсолютную безопасность. Подключение новых провайдеров, публикация репозитория и открытая регистрация требуют отдельной оценки данных и доступа.


## Content Security Policy

[proxy.js](../../proxy.js) создаёт 144-битный случайный nonce на каждый ответ страницы, перезаписывает недоверенные входящие CSP/nonce и передаёт nonce Next.js, скрипту темы и `ThemeStyle`. При SPA-навигации/refresh стили сохраняют nonce исходного документа. API, статические chunks, шрифты, worker и медиа исключены; sandbox для SVG `/api/assets/:id` остаётся отдельным и более строгим.

Выбран nonce для установленного Next.js 16.3.6: HTML/RSC и тема зависят от запроса, а корневой layout **уже** был `force-dynamic` до этого изменения. Новых динамических страниц нет. Страницы имеют `private, no-store`: нельзя кешировать HTML с nonce на CDN/nginx. Кеширование JS/CSS/шрифтов и медиа сохраняется. Hash/SRI не выбран для меняющихся inline-данных; экспериментальную сборку ради SRI не включаем. Proxy не читает БД, не делает сетевых запросов, добавляет генерацию nonce и сборку заголовка. Tiptap получает `injectNonce` для своего CSS.

Как предусмотрено [CSP3 strict-dynamic](https://www.w3.org/TR/CSP/#strict-dynamic-usage), доверенные скрипты могут загружать дочерние скрипты программно. Поэтому nonce блокирует инъекцию в HTML, но не является sandbox для уже доверенного JS. В текущем коде динамический SDK URL фиксирован в `lib/yandex-maps.js`; пользовательский ввод не задаёт URL скрипта.

Ресурсы и ограничения:

| Ресурс | Разрешение |
|---|---|
| Next, theme bootstrap, lazy imports | `script-src` nonce + `strict-dynamic`, `self`/SDK domains как fallback; нет production `unsafe-eval`/`unsafe-inline`; обработчики HTML запрещены |
| CSS сайта, изменяемая тема | `style-src` self + nonce; отдельно `style-src-attr unsafe-inline` для React layout, rich text и позиционирования карт |
| Фото, SVG-графика, локальные previews | `img-src self data: blob:`; SVG по-прежнему sandboxed |
| Шрифты, API и трекер | шрифты/API self; ошибки идут на свой сервер, DSN не разрешается браузеру |
| MapLibre / OSM | локальный `/maplibre/maplibre-gl-worker.mjs`, worker self/blob; тайлы `tile.openstreetmap.org` |
| Яндекс v3, raster renderer | `api-maps.yandex.ru`, его поддомены, `yastatic.net`; изображения/соединения также `*.maps.yandex.net`; SDK worker data/blob; search/suggest/routing не используются и не разрешаются |
| Пользовательский raster/style | оператор добавляет точные HTTPS origins в `CSP_MAP_ORIGINS` для connect/img, включая зависимости style JSON; без wildcard, credentials, paths или query |

Яндекс документирует `unsafe-eval` для **векторного** движка; ColaBike использует raster и не добавляет это разрешение глобально. Fixture проверяет интеграцию загрузчика/renderer, но не подтверждает текущую production-версию SDK и доступность тайлов. Перед enforcement обязательна проверка живого провайдера с ограниченным ключом; при несовместимости оставить Report-Only и устранить конкретную причину. Не разрешать `https:`/`*` для подавления отчётов.

`report-uri /api/csp-reports` работает отдельно от `/api/client-errors` (его JSON-схема несовместима с CSP). Приёмник понимает `application/csp-report` и `application/reports+json`, принимает только отчёты своего origin, максимум 16 KiB/10 записей. Бюджет 30 запросов на доверенный IP и 120 глобально за 15 минут; одинаковая очищенная запись логируется один раз за 15 минут через существующий DB rate limiter. Вывод: `csp_violation`, директива, класс маршрута/источника, disposition. Политика, nonce, URL, query, фрагменты, source-file, referrer, sample и payload не логируются и в сторонний трекер не отправляются. Неизвестные источники сведены к `external`; точную причину оператор смотрит в DevTools локально. Отчёты не являются доказательством атаки или отсутствия нарушений.

### Включение и откат оператором

1. После deployment оставить `CSP_MODE=report-only` (значение по умолчанию). Проверить заголовки страницы и поступление контрольного отчёта; отсутствие записей само по себе не означает совместимость.
2. Пройти Chromium/WebKit, desktop/mobile, light/dark: login/registration, редакторы статей/журнала, загрузка фото, админка, карта OSM и живой Яндекс с production-ключом, пользовательские источники при их использовании. Не публиковать ключ/URL отчётов с данными в issue.
3. После принятия результатов явно задать `CSP_MODE=enforce` в env и пересоздать app обычной процедурой deployment. Это runtime-параметр; истечение недели ничего автоматически не переключает. Проверить блокировку контрольного inline-script без nonce и работу разрешённых скриптов.
4. Откат: `CSP_MODE=report-only`; аварийный `off` убирает расширенную политику/отчёты, но сохраняет baseline `base-uri/object-src/frame-ancestors` и SVG sandbox. Пересоздать app; очистка CDN не требуется, HTML no-store. Неизвестное значение режима считается ошибкой конфигурации.

Официальные источники: [Next.js CSP](https://nextjs.org/docs/app/guides/content-security-policy), [Next.js Proxy](https://nextjs.org/docs/app/api-reference/file-conventions/proxy), [Яндекс v3 CSP](https://yandex.ru/maps-api/docs/js-api/common/connection/csp.html). Живые карты и применение env на VPS остаются внешней приёмкой владельца.


Локальный замер этого этапа: production build main `a454d7a` и сборка с CSP, Node 24.19.0, одно соединение PGlite, 5 прогревочных + 40 последовательных GET до полного чтения тела на маршрут. `/about`: p50/p95 26.5/41.3 → 37.7/65.9 мс; `/bikes`: 19.1/29.1 → 16.3/27.9 мс. HTML вырос примерно на 0.9/1.1 KiB из-за nonce. Обе сборки оставили страницы динамическими и HTML no-store; статические ресурсы не меняют режим кеша. Разнонаправленные времена показывают шум локального замера, а не обещание production latency; перед enforcement оператор сравнивает реальные TTFB/нагрузку.
