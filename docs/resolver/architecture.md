# Архитектура Bike Resolver

[Оглавление](../README.md)

## Назначение и граница

Bike Resolver — дополнительный детерминированный сервис восстановления заводской комплектации. Он не использует LLM или headless browser и не записывает `bikes`/`components`. Приложение владеет пользователем, preview, текущей сборкой и импортом; Resolver — поиском источника, извлечением, нормализацией, cache и схемой `bike_resolver`.

Браузер → авторизованный API приложения → [bike-resolver-client.ts](../../lib/bike-resolver-client.ts) / [resolver-proxy.ts](../../lib/resolver-proxy.ts) → внутренний Fastify. Порт 8080 не должен публиковаться наружу. Приложение продолжает работать вручную при отказе сервиса.

## Поток данных

1. Вход `{brand, model, trim, year}` валидируется; `candidateId` — непрозрачный ID из предыдущей выдачи, не произвольный URL.
2. Выбирается официальный адаптер, discovery получает кандидатов, matching определяет однозначность. Запрошенный год не считается доказательством года страницы. Если адаптера нет, он выключен или не дал точного совпадения, поиск продолжается по [реестру магазинов](#магазины-выбор-и-отчёт-поиска).
3. Safe HTTP client получает документ. Контент не исполняется: анализируются HTML и инертные структурированные данные.
4. Несколько ограниченных extraction-стратегий формируют raw fields; общий collector нормализует типы, сохраняет provenance, unknown и конфликты.
5. Возвращается один результат источника либо список вариантов на выбор. Приложение показывает результат пользователю и создаёт owner-bound preview; сохранение/импорт выполняется отдельно. Один импорт — одна спецификация одной страницы: детали разных страниц не склеиваются.

## Режимы HTTP

`POST /v1/resolve` сначала использует official flow; необязательный `sourceUrl` может быть fallback. Явный `/v1/resolve-url` и stream с `sourceUrl` идут сразу к указанной странице и имеют приоритет над `candidateId` и поиском. `candidateId` разрешается в ту страницу, которую предлагала прошлая выдача (см. ниже), а не в новый автоподбор. Когда нет URL/candidate, включённый `retailerSearch` ищет варианты в магазинах после неуспеха официального пути; результат магазина всегда приходит списком `ambiguous` и становится спецификацией только после выбора. `chooseCandidates:true` (мастер) строит единый список вариантов с отчётом. Это не неограниченный веб-поиск и не гарантированная поддержка любой марки.

`POST /v1/resolve/stream` возвращает NDJSON: строки `{type:"event",...}` и итоговый `{type:"result",result:...}`. UI показывает реальные события и количества, не выдуманный процент. Отмена должна распространяться через app proxy до ожидания DNS/очереди/fetch.

Дополнительно: `/v1/brands`, `/v1/photos/search`, `/v1/photos/:id`, `/health`, `/ready`, `/version`. `/internal/settings`, `/internal/cache`, `/internal/diagnostics` доступны через административный gateway; при production token они требуют Bearer. Остальные маршруты сервиса не являются заменой пользовательской авторизации приложения — изоляция сети обязательна.

## Магазины, выбор и отчёт поиска

Цепочка: **прямой адаптер или архив → при отсутствии адаптера, его отключении или неточном совпадении — все включённые магазины → проверенные варианты → выбор → preview → явный импорт.** Неоднозначный официальный результат не «разрешается» более слабым магазинным совпадением: магазины опрашиваются, только когда официальный источник не нашёл точной модели (все слова модели и комплектации, год совпадает или не указан в запросе).

`SourceSearch` обходит источники независимо. Фаза 1 — официальный адаптер (до 6 страниц) и архив моделей для прошлых лет; фаза 2 — каждый включённый магазин реестра и веб-поиск параллельно, каждый в своём бюджете. Тайм-аут, 403/429 или отказ одного источника не уничтожают найденное другими. Глобального отсечения «первые три источника» нет; пределы явные и общие для запроса:

| Предел                               | Значение                                            |
| ------------------------------------ | --------------------------------------------------- |
| Бюджет магазина / страницы / веба    | 14 с / 12 с / 12 с, общий запрос — не более 90 с    |
| Страниц магазинов за поиск           | 12 на все магазины поровну, не более 4 на магазин   |
| Страниц официального / архива / веба | 6 / 6 / 3                                           |
| Вариантов в выдаче                   | 12                                                  |
| События прогресса                    | Общий потолок 240; страницы проверяются без событий |

Страница каждого варианта проверяется общим extractor: не меньше трёх компонентов, год и название берутся из самой страницы, расхождение с запросом остаётся предупреждением `identity_mismatch`. Разные годы, трансмиссии и поколения рам — разные варианты; дедупликация объединяет только локализованные страницы одного товара магазина (`productKey`) и оставляет остальные ссылки в `alternatives`. Варианты с подтверждённым другим годом ранжируются ниже подходящих и неизвестных.

Карточка выбора (`BikeCandidate`) — источник (`kind`: `manufacturer`, `distributor`, `archive`, `store`, `web`; `storeId`), название, `year` или `null`, `drivetrain` (навеска, чтобы различать варианты), `quality` (полная или частичная, число компонентов), `warnings`, миниатюра и `alternatives`. Выдача магазина всегда помечена: комплектация магазина может отличаться от заводской. Даже единственный вариант требует явного выбора.

`candidateId = sha256(sourceIdentity(url))`. Реестр кандидатов процесса помнит страницу каждого предложенного ID 2 часа и разобранную копию — 20 минут: выбранное — ровно то, что видел пользователь, без второго поиска. Неизвестный или просроченный ID (в том числе после рестарта) даёт `not_found` с `reason: candidate_expired`, а не молчаливый новый выбор; в клиенте — «повторите поиск». Для марки с adapter страницу по ID можно найти заново только если adapter всё ещё её предлагает; иначе вместо нового списка тоже `candidate_expired`. Выбранная официальная страница сохраняет adapter, его версию и бренд в provenance (`source.kind: "manufacturer"`), вставленный адрес остаётся `manual-url`. Выбранный кандидат магазина не попадает в adapter производителя ни в `/v1/resolve`, ни в stream, ни через прокси приложения; preview по-прежнему создаёт только приложение для владельца.

Ответ `ambiguous`, `not_found` и `upstream_unavailable` может содержать `search`: по строке на источник — `id`, `name`, `kind`, `status` (`ok`, `empty`, `blocked`, `timeout`, `unavailable`, `skipped`, `disabled`), `reason`, число проверенных страниц и найденных вариантов, длительность — и `complete`. Ограниченная выдача не называется полной: `complete` истинно, только если все включённые источники ответили без усечения. Пустой результат при недоступных источниках — `upstream_unavailable`, а не `not_found`. Если у источника часть страниц не ответила (`http_403`, challenge, таймаут), а остальные лишь не подошли, статус источника — отказ, а не `empty`: не ответившая страница могла быть нужной.

Реестр: `/v1/brands` отдельно перечисляет `brands` (`kind: "direct"` — адаптер официального сайта, `kind: "distributor"` — официальный магазин импортёра, когда сайт производителя спецификацию не публикует; `limitation` — честная пометка, не выключатель) и `stores` (`enabled`, `search`, `domains`, `limitation`) и `storeSearch`. Марка без адаптера допустима: её ищут только магазины. Флаги магазинов лежат в `settings.stores`; отсутствующий ключ берёт значение по умолчанию, сохранённые оператором флаги не перезаписываются.

Страница с несколькими сборками (TWITTER: «System Configuration», ячейки таблицы по сборке) не склеивается: каждая сборка — свой кандидат с адресом `…?build=<метка>`, и разбор оставляет только её строки. Ссылка без выбора сборки берёт первую и добавляет предупреждение `multiple_builds` («выбрана одна из нескольких»). Предиктивный поиск витрины Shopify (`/search/suggest.json`, публичный endpoint строки поиска магазина) даёт адреса, типы и описания; тип отсекает рамы, детали, детские и бывшие в употреблении велосипеды.

## Результат и качество

Статусы: `resolved`, `ambiguous`, `not_found`, `unsupported_brand`, `upstream_unavailable`, `parse_error`. `unsupported_brand` остаётся только когда ни один источник не может обслужить запрос (сервис выключен либо нет ни адаптера, ни включённого поиска по магазинам). `quality.level=partial` может сопровождать `resolved`: это полезность извлечения, а не доказательство совпадения модели. В текущем extractor меньше трёх распознанных компонентов — parse error; complete требует минимум восьми и покрытия не ниже 65%. Год, confidence, warnings и unknown fields оцениваются отдельно.

`source` результата содержит `kind` (`manufacturer`, `distributor`, `archive`, `store`, `web`, `manual`) и `storeId`; у старых preview поля нет, и клиент определяет источник по `adapter`. У компонента сохраняются исходные label/value, URL, стратегия и confidence. SourceYear может быть null. Противоречивые значения не склеиваются в выдуманный компонент. Цена магазина не импортируется как цена покупки владельца. Подсказки веса/цвета применяются явно, с сохранением источника.

## Cache и ограничения

Ключ official cache включает нормализованную идентичность, candidate, adapter version и версии extractor/schema. Кэшируются `resolved` и действительный `not_found`, но не сетевой отказ как отсутствие модели. Ручные URL читаются заново. Непотоковые совпадающие обращения могут объединяться; stream-запросы имеют собственный cancellation context.

Часть discovery, photo IDs и диагностики process-local. Перезапуск уничтожает временные photo IDs; `/ready` проверяет cache storage, не доступность всех производителей. Для расширения: [источники](sources.md); для ошибок: [диагностика](diagnostics.md).

## Запрос без модельного года

`querySchema.year` допускает `null` и по умолчанию не подставляет текущий год. Поиск с неизвестным годом возвращает варианты и требует явного выбора; архивный URL с `null`/выдуманным годом не строится. Указанный год остаётся строгим ограничением, отдельная комплектация не смешивается с соседней. После извлечения `sourceYear` заполняется только из источника. Если владелец на последнем шаге указывает другой год, сервер требует `identityConfirmed`; исходный preview/factory-снимок сохраняет первоначальный запрос и происхождение. Смена марки/модели/комплектации инвалидирует preview. Регрессия: `tests/unknown-year.test.ts`.
