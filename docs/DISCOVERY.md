# Журнал и поиск опыта

Миграция `015_discovery.sql` применяется обычным runner до запуска новой версии.
Главная остаётся витриной. `/journal` — публичные истории, `?mode=following` —
истории авторов **или** велосипедов, на которые подписан читатель. Это тот же
`rideFeed` и `/api/community/feed`, не параллельная лента. `/feed` сохраняет
велосипеды и покатушки и добавляет записи; `/feed?type=rides` остаётся маршрутам.
При наличии видимой записи с прикреплённой покатушкой смешанная лента показывает
запись, а не второе событие маршрута. Нет автоматических историй или fan-out
уведомлений о публикации. Ответы, жалобы, лайки и модерация остаются прежними.

## Доступ и учёт

Подписка на велосипед и сохранение доступны любому вошедшему пользователю,
включая читателя без велосипеда. `/saved` — личный список. При каждом чтении
проверяются текущие публикация/публичность записи, публичность велосипеда и блок
автора. Скрытое не входит ни в выдачу, ни в total, ни в похожие сборки. Сохранённая
ссылка не является разрешением доступа. Удалить сохранение/подписку можно и после
скрытия; удаления каскадируются. Прямые фото по-прежнему защищены journal media API.

Минимальный внутренний учёт: дневные счётчики первого публичного опубликования
записи, новых подписок и сохранений. Повторный идемпотентный PUT не считается.
Отписка/повторная подписка — новое действие. Черновик и приватная публикация не
считаются; при последующем публичном сохранении запись учитывается один раз.
Нет текста, IP, User-Agent, адресов, целевых bike/entry IDs. Случайный ключ участника
позволяет считать возвраты по разным дням. Это **псевдонимный**, не анонимный учёт:
служебная таблица связывает ключ с аккаунтом ради каскадного удаления. Ключи никогда
не выдаются клиенту. Только администратор видит агрегаты за 30 дней в обзоре.

## Поиск и справочники

`/search` расширяет вход глобального поиска: велосипеды, журнал, пользователи.
Байки используют существующий showcase DTO/карточки. `/experience` использует ту же
выдачу для страниц моделей/деталей: сборки, журнал, вопросы. Страницы вычисляются
из имеющегося публичного контента; нет предварительно созданных пустых моделей
или форумов. Из карточки байка доступны похожие сборки: модель/марка, категория и
первое назначение; самосборы без модели сопоставляются по категории/назначению.

Фильтры: марка, модель, год, компонент, назначение. Назначений максимум 12; начальные
пять — город/путешествия/спорт/зима/самосбор. Управление — Справочники → Поиск и опыт.
Отключённое назначение не предлагается новым сборкам, старое сохраняется. Свободные
марки/модели/компоненты допустимы. Название модели компонента плюс категория —
каноническая справочная идентичность; `components.id` — конкретная установка на
велосипеде. Снимок в журнале сохраняет именно установку и её прежние поля, поэтому
поиск записей по компоненту смотрит снимки, а не сегодняшнюю комплектацию.

Нормализация игнорирует регистр, пробелы, пунктуацию и ё/е. Управляемые варианты
позволяют связывать кириллическое и латинское написание. Они живут в существующем
версионированном `site_catalog`, не во втором справочнике. Объединение дубля добавляет
вариант и объединяет подсказки, не переписывая авторский текст/снимки. Область правила
— марка для модели, категория для детали; циклы и повторные варианты запрещены.
Это управляемое соответствие, не догадка о совместимости по похожим словам.

В установке необязательный результат: без доработок / с доработками / не подошло.
У вопроса только автор выбирает существующий видимый ответ этого вопроса. При
удалении/блокировке ответа отметка перестаёт показываться. UI обозначает пользовательский
опыт, контекст байка и число публичных свидетельств, а не гарантию безопасности.

SQL параметризован, выдачи по 24, фильтры ограничены. Нет N+1 карточек; нормализация
текста и JSON-снимков пока вычисляется в запросе. Для большого объёма потребуется
профилирование и поисковый индекс с той же динамической приватностью, не кэш всех
приватных текстов. Запросы total и списка — отдельные statements, как в витрине;
уже полученную браузером информацию невозможно отозвать задним числом.

## Проверки

`discovery.test.js`, `discovery-http.js`, `e2e/discovery.spec.js`: читатель без байка,
обе подписки без дублей, сохранённое, поиск написаний/самосборов/пустых результатов,
снимки старых деталей, решение с проверкой владельца, скрытие в выдачах/total/
уведомлениях. Предыдущие journal-тесты продолжают проверять прямой доступ к медиа.
Браузерные проекты: Chromium и WebKit mobile. Навигация/контролы/карточки следуют
VISUAL_DESIGN_SYSTEM.md и DENSE_UI.md; кастомные icon overrides сохранены.
