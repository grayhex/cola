# Яндекс Карты в покатушках

## Включение

В **Админка → Система → Карта** выберите **Яндекс Карты · JavaScript API 3.0**,
включите подложку, вставьте ключ продукта **JavaScript API** в поле
**API-ключ Яндекс Карт** и сохраните настройки. Затем обновите страницу покатушки.
Ключ задаётся в существующем `map.publicKey`; OAuth Client Secret здесь не нужен.
Новые переменные окружения, сервисы и миграции БД не требуются.

Ключ браузерный и виден посетителям. В кабинете Яндекса ограничьте его по HTTP
Referer доменом `colabike.ru`. Для разработки используйте отдельный разрешённый
домен/ключ; production-настройка не предназначена для `192.168.1.200`.
Учитывайте тариф и ограничения своего ключа в кабинете Яндекс Карт.

Документация провайдера:
- [Быстрый старт и активация ключа](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html)
- [Ограничения по HTTP Referer](https://yandex.ru/maps-api/docs/js-api/limit.html)
- [YMap](https://yandex.ru/maps-api/docs/js-api/map/YMap.html)
- [YMapFeature](https://yandex.ru/maps-api/docs/js-api/object/geo-objects/YMapFeature.html)

## Отображение и расход API

Яндекс используется через официальный SDK `https://api-maps.yandex.ru/v3/`.
Недокументированные XYZ-тайлы, проксирование карт через VPS, скачивание тайлов
про запас и вызовы API построения маршрутов не используются.

Полноценная карта создаётся только для видимой страницы/редактора покатушки.
В списках и маленьких карточках `RideBasemap` показывает SVG-линию без загрузки
SDK и без запросов к OSM. В режимах «Только линия», «Не показывать карту», при
выключенной подложке или полностью скрытой геометрии SDK не загружается.
Прокрутка карты за пределы экрана и обратно не пересоздаёт её.

Скрипт общий для всего документа. Параллельные обращения используют один Promise;
ошибки не вызывают бесконечные повторы. Смена ключа после загрузки SDK требует
полного обновления страницы, иначе посетитель увидит понятное сообщение.

Яндекс отображает собственные логотип и авторство. Они не скрываются и не
перекрываются контролами; OSM-атрибуция на Яндекс Карте не добавляется.
Колесо масштабирует карту только при включённой личной настройке `mapScrollZoom`.
Доступны кнопки масштаба и возврата ко всему маршруту.

## Приватность и ошибки

Карта использует **только geometry из существующего API покатушек для текущего
посетителя**. Никакого повторного чтения оригинального GPX на клиенте нет.
Координаты передаются как `[longitude, latitude]`. Раздельные сегменты рисуются
отдельными `LineString`, без соединения разрывов приватности и GPS.
Маркеры указывают границы *видимой* части, а не скрытые исходные старт/финиш.
Провайдер карты остаётся внешним сервисом, которому браузер отправляет запросы
подложки; это следует учитывать в политике конфиденциальности сайта.

При ошибке загрузки/готовности SDK, пустом ключе или отсутствии отрисованных
тайлов до таймаута отображаются линия маршрута и сообщение. SVG остаётся видимым
во время загрузки. Изменение настроек и уход со страницы уничтожают экземпляр карты
и отменяют таймеры. Исходная ошибка провайдера с URL/ключом в UI не выводится.

Выбор Яндекса имеет приоритет над legacy `MAP_STYLE_URL`. Для остальных провайдеров
старое поведение `MAP_STYLE_URL` сохранено. OSM остаётся провайдером по умолчанию;
обновление приложения само не переключает уже работающие карты.

## Nginx

Страница должна разрешать отправку **origin**, но не приватного URL покатушки,
в cross-origin Referer. `next.config.mjs` и обновлённый nginx-шаблон используют:

```nginx
add_header Referrer-Policy strict-origin-when-cross-origin always;
```

Деплой приложения не переписывает `/etc/nginx/conf.d/colabike.conf`. Для старой
установки проверьте заголовок и, если там остался `same-origin`, исправьте его:

```bash
curl --max-time 10 -sI https://colabike.ru/ | grep -i referrer-policy
sudo sed -i 's/Referrer-Policy same-origin/Referrer-Policy strict-origin-when-cross-origin/' /etc/nginx/conf.d/colabike.conf
sudo nginx -t && sudo systemctl reload nginx
```

Не публикуйте nginx-конфиг целиком: в нём может находиться `TRUSTED_PROXY_KEY`.
При собственной ужесточённой CSP проверьте разрешения для SDK и ресурсов Яндекса,
не отключая CSP целиком. Штатная CSP ColaBike загрузку SDK не запрещает.

## Проверки

```bash
node --test tests/yandex-maps.test.js tests/map-settings.test.js
```

Тесты загрузчика и рендера используют поддельный SDK, не реальные ключи и не
платные запросы. Проверяются дедупликация, таймауты, отказ загрузки, смена ключа,
отмена при уничтожении карты, координаты, раздельные сегменты и отсутствие
случайных OSM-запросов для Яндекса. Серверная схема проверяет сохранение нового
провайдера и обязательность ключа при включённой подложке.

При приёмке на разрешённом домене проверьте публичную покатушку, старт/финиш,
«Весь маршрут», колесо, мобильную ширину, режимы без подложки и возврат к OSM.
Без настоящего ключа и разрешённого домена живую авторизацию SDK проверить нельзя.
