# ColaBike

Личный велогараж: фотографии, актуальная комплектация, аксессуары и публичная карточка по ссылке. Next.js + PostgreSQL. Интерфейс на русском.

## Локальный запуск через Docker

Нужен Docker Desktop / Docker Engine с Compose.

```sh
git clone https://github.com/grayhex/cola.git
cd cola
docker compose up --build -d
```

Откройте http://localhost:3000 и создайте аккаунт. Демо на главной доступно без регистрации, его сборка иллюстративная и не заявлена как заводская комплектация. У новых пользователей пустой личный гараж.

Миграции применяются автоматически до запуска приложения. PostgreSQL и фотографии сохраняются в именованных volumes `database` и `photos`. Обычный `docker compose down` сохраняет данные. **Не используйте `down -v`, если данные нужны.** База не выставляется наружу.

```sh
docker compose logs -f app
docker compose down
```

## Возможности

- Регистрация email/пароль (от 10 символов), вход и выход; пароли хешируются scrypt, случайные сессии хранятся в БД в виде SHA-256, cookie HttpOnly / SameSite.
- Несколько велосипедов: имя, марка, модель, год, категория, размер, вес, цвет, описание.
- До 12 фотографий на велосипед, JPEG/PNG/WebP до 10 МБ; выбор обложки и удаление. Изображения декодируются, уменьшаются до 2400 px, перекодируются в WebP без EXIF.
- Отдельные вкладки комплектации и аксессуаров, добавление/изменение/удаление деталей, необязательная цена в рублях. Хранится только актуальное состояние.
- Редактируемые в админке справочники марок и моделей gravel/MTB/road, производителей, категорий и моделей компонентов; ручной ввод разрешён. `lib/catalog.js` используется только для первого наполнения. Данные хранятся в PostgreSQL; база не подставляет заводские сборки и не проверяет совместимость.
- Приватность по умолчанию. Включаемая ссылка `/b/<uuid>` показывает фото и детали, но не цены и почту. Закрытие доступа меняет токен; старые ссылки не оживают при повторной публикации. Авторизация проверяется и на чтении фотографий, кэширование приватных ответов отключено.
- Ограничение попыток входа и регистрации в PostgreSQL, проверка Origin для изменений, параметризованные SQL-запросы и серверная валидация.
- Админка `/admin`: оформление, 147 текстов интерфейса, справочники, управление пользователями, медиатека и журнал действий.
- Светлая, тёмная и системная темы, пять шрифтов, цвет, скругления, порядок основных блоков и положение паспорта. Mobile first: одна колонка на телефоне, расширение сетки через `min-width` в `app/mobile.css`.
- Фото без внешних полей и без обрезки по умолчанию. Можно включить кадрирование с выбранными пропорциями. Нажатие на фото открывает его целиком. Собственные SVG-иконки для всех категорий навески и аксессуаров.

## Обновление и первый администратор

Если приложение уже установлено:

```sh
git pull
docker compose up --build -d
```

Миграция `002_admin` автоматически добавит настройки и роли, сохранив существующие аккаунты, велосипеды и фотографии. Все старые и новые пользователи получают роль `user`. Обновления не перезаписывают уже отредактированные настройки и справочники.

Зарегистрируйте свой аккаунт (или используйте существующий) и один раз выполните, подставив его email:

```sh
docker compose exec app node scripts/set-admin.js you@example.com
```

Обновите страницу, перейдите по ссылке «Админка» в шапке или откройте http://localhost:3000/admin. Команда не создаёт пароль, а назначает права существующему аккаунту. Далее другие роли можно назначать из админки. Нет общего пароля администратора, автоматического повышения первого пользователя или публичного маршрута выдачи прав.

Возможности админки:

- **Обзор:** название и описание сайта, включение регистрации, демонстрационного велосипеда и подписи в шапке.
- **Оформление:** тема, шрифт, акцент, скругления, положение паспорта, порядок фото/комплектации, выравнивание заголовков, число колонок гаража, режим и пропорции фото, логотип, favicon, фото демо и графика гаража.
- **Тексты:** поиск и редактирование заголовков, кнопок, названий полей и подсказок. Сброс отдельных переопределений. Пользовательские записи и технические сообщения сервера не являются текстами оформления.
- **Справочники:** добавление, переименование, удаление и сортировка записей; отдельные модели по маркам и типам велосипедов, производители компонентов, категории навески/аксессуаров, модели деталей, назначение иконок. Изменения касаются подсказок и не переписывают сохранённые велосипеды. После переименования категории её прежние модели можно скопировать в новую категорию.
- **Пользователи:** поиск и постраничный список, изменение имени/email, роли, блокировка, завершение сессий, удаление аккаунта вместе с его велосипедами и фото с подтверждением email. При блокировке закрывается доступ и к публичным велосипедам. Собственные права снять нельзя; администратора перед удалением нужно понизить до пользователя.
- **Медиа:** загрузка JPEG/PNG/WebP с перекодированием в WebP, просмотр и удаление. Медиатека предназначена для публичных изображений сайта. Используемое изображение сначала нужно заменить в оформлении, затем его можно удалить.
- **Журнал:** последние 100 действий. Изменения пользователей и настроек записываются вместе с идентификатором администратора.

Кнопка «Сохранить» публикует настройки или справочники. Несохранённые изменения можно отменить; при закрытии вкладки браузер предупреждает о них. Версии защищают от перезаписи изменений другого администратора. Полный конструктор произвольной вёрстки не используется: расположение выбирается из адаптивных вариантов. Доступ к БД, HTTPS, `APP_ORIGIN` и cookie остаются в окружении сервера, а не в публичной конфигурации.

## Настройка

При стандартном локальном запуске `.env` не обязателен. Для изменения настроек скопируйте `.env.example` в `.env`. Если открываете с другого устройства, укажите точный `APP_ORIGIN`, например `http://192.168.1.20:3000`. Не добавляйте завершающий `/`.

Для хостинга: установите надёжный `POSTGRES_PASSWORD` до первого создания БД, внешний HTTPS origin в `APP_ORIGIN` и `COOKIE_SECURE=true`; используйте reverse proxy с HTTPS и ограничением размера тела запроса 11 МБ. Пароль должен быть URL-safe либо отдельно задайте корректно экранированный `DATABASE_URL` в Compose. Смена переменной пароля не меняет пароль уже созданного PostgreSQL volume.

Перед публичным запуском потребуется почтовый провайдер для подтверждения адресов и восстановления паролей — эти сценарии пока не реализованы. Нет OAuth. Сессии истекают через 30 дней. Регистрация не создаёт демонстрационные учётные записи. Справочник расширяется в админке.

Фотографии пользователей лежат только в локальном volume. Для резервной копии сохраняйте PostgreSQL (`pg_dump`) и volume фотографий вместе. Переход на S3 можно выполнить отдельно при выборе хостинга.

## Разработка и проверки

Node.js 22+, pnpm 11.19.0. Для запуска без Docker нужна работающая PostgreSQL и переменные окружения из `.env.example` (Next.js читает `.env.local`; CLI миграции запускайте с `node --env-file=.env.local scripts/migrate.js`).

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

Тесты используют PostgreSQL-движок PGlite в памяти: проверяют изоляцию владельцев, скрытие цен, отзыв ссылки, каскадное удаление, валидацию, пароли, безопасные настройки, покрытие категорий иконками, сохранность старых данных при миграции и защиту администраторов. Это не заменяет запуск Docker на целевой машине.

Для HTTP-проверок используйте **только отдельную временную БД**. `scripts/test-db.js` поднимает PGlite на `127.0.0.1:5432` без сохранения данных; не запускайте его рядом с рабочей БД на этом порту. Направьте приложение и тесты на эту базу через `DATABASE_URL`, запустите приложение, затем `node tests/http-smoke.js` и `node tests/admin-http.js`. Тесты создают служебные учётные записи; второй тест временно меняет настройки и назначает тестового администратора. Для другого адреса приложения задайте `TEST_ORIGIN`, совпадающий с `APP_ORIGIN`.

## Демо и источники справочника

Изображение демо загружается с сайта [Canyon](https://www.canyon.com/en-si/outlet-bikes/gravel-bikes/grizl-al-7-raw/50051247.html), с указанием источника в карточке; для него нужен интернет. Пользовательские фотографии работают локально. Внешнее фото используется только как визуальная демонстрация, права остаются у Canyon. Перед коммерческой публикацией замените его собственной фотографией или лицензированным изображением.

Названия компонентов сверены с [Shimano](https://bike.shimano.com/en-UK/bike-selector.html) и [Brooks](https://www.brooksengland.com/pages/faq); справочник содержит также общеупотребимые наименования других производителей, не является каталогом актуального наличия и не гарантирует совместимость. Шрифт Manrope загружается с Google Fonts; при отсутствии сети используется Arial.

Иконки навески в `lib/part-icons.js` нарисованы специально для ColaBike и не используют изображения Flaticon. Они масштабируются без потери резкости и наследуют цвет текущей темы.

### Автоматическая заводская комплектация

Bike Resolver запускается отдельным сервисом в том же `docker compose up --build -d`.
В админке появился раздел **Bike Resolver**: настройки автопоиска, адаптеры и очистка кеша.
При создании велосипеда заполните марку, модель и год либо введите полное название, например `Giant Contend AR 1 2024`, и перейдите к следующему полю. Найденные компоненты добавятся при сохранении. Для существующих велосипедов импорт запускается явно и не заменяет текущие детали.

По умолчанию включены Giant, Canyon и Specialized. Остальные источники отключены из-за недоступных данных или неподтверждённого года; ограничения видны в админке. CUBE Travel SL 2020 пока не проходит live-разрешение. См. [документацию сервиса](services/bike-resolver/README.md).

## Мастер добавления — 0.3.0

Добавление нового велосипеда проходит в четыре шага с общим прогрессом и возвратом назад:

1. Производитель, модель, год и версия комплектации. Название в гараже необязательно; пустое название автоматически заменяется идентификацией модели.
2. Проверка поддержки производителя и автоматический поиск. При неудаче — ссылка на страницу магазина, повторные попытки или переход к ручному заполнению. Ограничения доменов/недоступных производителей остаются действующими.
3. Редактирование найденных компонентов или ручное заполнение по настраиваемым группам. Поисковые списки показывают максимум 8 совпадений, поддерживают клавиатуру и собственные значения.
4. Автоматический поиск фотографий без ввода ссылки, выбор до 3 найденных снимков или загрузка своих; тип велосипеда, цвет, ростовка, цена, вес, пробег, описание, ссылка производителя и публичность.

До финального сохранения велосипед не создаётся. Сервер одной транзакцией сохраняет велосипед и отредактированные компоненты; заводской результат берётся только из серверного preview, привязанного к пользователю и идентификации. Preview действует 2 часа. Повторная отправка запроса идемпотентна. Фотографии загружаются после создания: при сбое можно повторить загрузку либо открыть уже сохранённый велосипед. Черновик живёт в открытом мастере, не восстанавливается после перезагрузки; закрытие/уход со страницы сопровождается предупреждением.

Админка → **Дизайн → Расположение элементов**: «Максимально компактно», «Сбалансированно», «Подробно». Компактный пресет уменьшает фото и шрифт, показывает группы в двух колонках; подробный делает большую фотографию и свободный одноколоночный список. Существующие настройки видимости/порядка блоков сохраняются. Любая длина комплектации остаётся доступна прокруткой, а не обрезается до одного экрана.

**Логотипы и графика**: загрузите файлы через «Медиа» и назначьте логотип и отдельные изображения MTB / шоссе / гравела. Изображение категории подставляется, только если собственных фотографий нет. Используемые изображения защищены от удаления.

Миграция `005_bike_wizard.sql`: пробег, временные preview парсера, идемпотентные отправки мастера. `tests/wizard.test.js` и `tests/wizard-http.js` проверяют ограничение справочников, транзакционное сохранение, права на preview, разделение заводских/текущих компонентов, повторную отправку, пробег и публичность.

## Карточка и импорт — 0.2.0

- Админка → **Группы деталей**: название, иконка, категории и порядок групп. В карточке стрелки меняют порядок групп; меню `···` у компонента — порядок внутри группы. В форме детали можно выбрать группу вручную. Аксессуары используют те же группы.
- **Блоки карточки**: включение, порядок и вид заголовка, фото, описания, галереи и комплектации; «О велосипеде» открыт по умолчанию. Поля описания можно скрывать отдельно. **Тексты** собраны в раскрываемые разделы.
- В форме велосипеда есть ссылка на производителя, цена и три независимых переключателя видимости цены велосипеда / компонентов / аксессуаров. По умолчанию цены скрыты, в том числе из публичного JSON. В деталях и аксессуарах можно сохранять ссылки.
- В поиске комплектации можно указать URL товара. Проверьте модель, год и показанные компоненты, затем подтвердите импорт. Существующие пользовательские детали сохраняются. Список дополнительных доменов настраивается в **Bike Resolver**.
- После создания предлагается найти фотографии. Поиск работает по каталогу производителя или указанной странице товара; выберите 1–3 фото. Можно открыть поиск повторно в карточке. Источник фото сохраняется; свои фото по-прежнему можно загружать вручную.
- В футере и разделе Bike Resolver показаны версии приложения/парсера и хеши сборок. Недоступность парсера отмечается отдельно.

Миграция `004_garage_layout.sql` добавляет ссылки, цены/видимость, порядок компонентов и групп, происхождение фото и временные пользовательские разрешения на загрузку найденных изображений. Настройки блоков/групп добавляются к прежним настройкам без сброса содержимого. Docker запускает миграцию автоматически; вручную: `npm run db:migrate`.

Проверки: `npm test`, `npm run build`, `npm test --prefix services/bike-resolver`, `npm run build --prefix services/bike-resolver`, `npm run test:integration`. Интеграционный сценарий использует временную БД и тестовый источник, проверяет импорт по URL, сортировку, права доступа к изображениям, повторную загрузку и версии. Сеть производителей не участвует в unit/HTTP-тестах. Ограничения живых CUBE/Velo-Port источников описаны в README сервиса.
