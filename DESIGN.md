# ColaBike — дизайн-система

Инструкция для людей и агентов, которые меняют интерфейс ColaBike. Здесь описано
то, что реально реализовано в коде (`app/styles/*`), и правила, по которым
добавлять новое. Живая витрина компонентов в обеих темах — **`/admin/ui-kit`**
(только администратор; в `next dev` — любой).

Если правило здесь расходится с кодом, прав код: исправьте код или этот файл
в том же PR.

## 1. Референсы

Визуальный язык взят со страниц Hugging Face **[Pricing](https://huggingface.co/pricing)**
и **[Storage](https://huggingface.co/storage)** (маркетинговый режим) и, по просьбе
владельца проекта, **[Datasets](https://huggingface.co/datasets)** (плотные списки,
фильтры, карточки-строки — рабочий режим). Изучены сохранённые HTML этих страниц:
разметка и классы Tailwind видны, но их `style.css` в сохранение не попал.

Поэтому значения делятся на три вида, и в таблицах ниже они помечены:

- **[разметка]** — прочитано из классов Tailwind в HTML референса (например,
  `max-w-7xl`, `border-gray-200/70`, `rounded-xl`, `shadow-xs`, `text-5xl
  font-black`). Числа — стандартная шкала Tailwind v4, то есть точные.
- **[приближение]** — стиль собственного класса Hugging Face (`.btn`, `.tag`,
  `.overview-card-wrapper`, `.form-input`), чей CSS недоступен. Воспроизведён по
  виду и известным фрагментам; **это не измеренные параметры оригинала**.
- **[ColaBike]** — собственное решение проекта (бренд, доступность, кириллица,
  плотность рабочих экранов).

Приложенный к задаче `design.md` (shadcn.io, «Hugging Face Design System»)
описывает **главную страницу** huggingface.co и расходится с Pricing/Storage.
Что взято и что нет:

| design.md | Pricing / Storage | Решение |
|---|---|---|
| «Два слоя»: тёмный герой `#0b0f19` на один экран, потом белое | Страница целиком в одной теме: белая в светлой, `gray-950` в тёмной; герой отделён линиями, а не цветом | Одна поверхность на тему; `#0b0f19` — фон тёмной темы |
| Основная кнопка белая на тёмном герое | Чёрная кнопка с двойным кольцом (`bg-black`, `ring gray-200 → black`), в тёмной теме — белая | Чёрная/белая кнопка по Pricing |
| Карточки без теней, радиус 8 px | Мини-карточки `rounded-xl` (12 px) + `shadow-xs` + `border-gray-200/70` | 12 px и `shadow-xs` для карточек, 8 px для кнопок и полей |
| Пилюли 25,6 px, цвета GitHub Primer (`#388bfd`…) | `rounded-full`, цвета Tailwind (`bg-blue-500/10 text-blue-600`) | `rounded-full`, палитра Tailwind |
| Заголовки без трекинга, 48/700 | `tracking-tight`, `font-black` (900) на героях, `font-bold` в разделах | `--weight-black` + `-0.02em` только для маркетинговых заголовков |
| IBM Plex Mono для кода | `font-mono` для служебных меток (`Base`, `50TB+`), ASCII-фона; на Datasets — имена репозиториев | Plex Mono для меток, чисел, имён в карточках-строках |
| Source Sans Pro везде | То же | Source Sans 3 (свободный преемник Source Sans Pro, с кириллицей) |

## 2. Принципы

1. **Одна система, два режима.** Маркетинговые страницы (`/about`, вводный блок
   главной) — крупная типографика, разлинованная колонка, «текст + демонстрация».
   Рабочие (витрина, велосипед, журнал, покатушки, профиль, формы, админка) — те
   же токены и компоненты, но плотно: фото и данные важнее украшений.
2. **Линии вместо заливок.** Глубину дают волосяные линии `--line` и пунктир;
   тени — только `shadow-xs` у карточек и большие тени у всплывающих слоёв.
3. **Цвет — это сигнал.** Интерфейс нейтральный (серая шкала). Цветом отмечаются
   тип велосипеда, состояние, тема раздела на маркетинговой странице и бренд.
   Главное действие — чёрное (белое в тёмной теме), а не жёлтое.
4. **Семантические токены.** Компоненты используют только назначения
   (`--text-muted`, `--line`, `--danger`), никогда сырые цвета и числа.
5. **Состояния обязательны.** У каждого интерактивного компонента есть
   наведение, нажатие, клавиатурный фокус, недоступность и, где нужно,
   ожидание и ошибка.
6. **Движение деликатное.** 150–300 мс, только прозрачность и небольшой сдвиг;
   `prefers-reduced-motion` отключает всё.

## 3. Архитектура CSS

Стек не меняется: Next.js, глобальные CSS + CSS Modules. Без Tailwind, shadcn,
Radix и библиотек анимации.

```
app/styles/tokens.css      токены и порядок слоёв (импортируется первым)
app/styles/fonts.css       @font-face: Source Sans 3, IBM Plex Mono
app/styles/base.css        элементы: body, заголовки, ссылки, фокус, reduced motion
app/styles/components.css  общие компоненты (раздел 7)
app/styles/layout.css      страницы: рабочий и маркетинговый режимы (раздел 6)
app/styles/<feature>.css   раскладка разделов из общих компонентов:
                           bike (детали карточек), bike-page (велосипед, мастер,
                           формы гаража), journal, community (обсуждения,
                           уведомления, ленты, поиск опыта), rides, game
                           (награды, зал славы), profile (профиль, кабинет),
                           articles, admin
app/**/*.module.css        стили одного React-компонента
```

Каскадные слои: `@layer tokens, base, components, layout, features;`

- Слой побеждает предыдущий независимо от специфичности, поэтому компоненты не
  нужно «перебивать» `.site-root .x`.
- CSS Modules вне слоёв и побеждают всё — используйте их для частного, а не для
  переопределения общих компонентов.
- Старые глобальные стили (globals, mobile, product-ui и другие) удалены в
  #127 вместе с переходными псевдонимами токенов (`--ink`, `--muted`,
  `--paper`…); используйте только семантические токены раздела 4.
- Inline-стиль `:root{--accent…}` из админки (Дизайн → Внешний вид) стоит вне
  слоёв и переопределяет брендовый цвет.

Правила:

- Числа только из шкал токенов. Нужен новый размер или цвет — добавьте токен
  сюда и в `tokens.css`, а не значение в модуль.
- Цвет задаётся по назначению в обеих темах: светлые значения в
  `:root, .theme-light, .theme-dark`, тёмные — в `:root[data-theme="dark"],
  .theme-dark` и в блоке `prefers-color-scheme` (он должен совпадать с тёмным).
- Перед добавлением компонента проверьте раздел 7 и UI Kit: скорее всего, нужное
  уже есть. Новый общий компонент — в `components.css` + UI Kit + этот файл.

## 5. Темы

- Выбор темы не менялся: «Системная / Светлая / Тёмная» в шапке, значение в
  `localStorage["cola:theme"]`, тема по умолчанию — в админке.
- Скрипт `themeBootstrap` (lib/theme.js) ставит `data-theme` на `<html>` до
  первой отрисовки — вспышки неправильной темы нет. Без JavaScript
  `data-theme="system"` следует `prefers-color-scheme`.
- Тёмная тема — не инверсия: фон `#0b0f19`, линии `#18212f`, кнопки-градиенты
  gray-800 → gray-950, приглушённый текст gray-400, состояния светлее
  (`*-400`), подложки прозрачные.
- `.theme-light` / `.theme-dark` перекрашивают часть страницы (UI Kit).

## 6. Компоновка

### Шапка и подвал

- **Шапка** (`app/ui/global-header.*`) — полоса 64 px по образцу референсов
  **[разметка]** `h-16 border-b border-gray-100`: бренд ColaBike (жёлтый знак +
  18/700), поиск-«пилюля» с `⌘K` от 1280 px, текстовые разделы с серыми
  линейными иконками, которые при наведении окрашиваются цветом раздела, затем
  тема, уведомления и аккаунт. Разделы раскрываются меню (`.menu`-вид); до
  1100 px всё уходит в боковую панель справа.
- **Подвал** (`social-primitives.jsx` → `SocialFooter`) — **[ColaBike, #124]**
  вместо многоколоночного подвала Hugging Face: одна строка — до четырёх
  логотипов из «Графики» слева (каждый со своей ссылкой), «ColaBike · Люди.
  Велосипеды. Истории.» строго по центру страницы, версии приложения и парсера
  справа. Дублей меню и ссылки на GitHub нет; документы — в конце «О проекте».
  На узких экранах три части идут столбиком по центру.

### Рабочий режим

```html
<main class="page">                       <!-- 1280 + поля; .narrow 768, .form 640 -->
  <div class="page-head">                 <!-- Datasets: имя, счётчик, поиск, действия -->
    <div class="page-title"><h1>Велосипеды</h1><span class="count">1 204</span></div>
    <label class="search-pill">…</label>
    <div class="page-actions">…</div>
    <p class="page-lead">…</p>            <!-- необязательно -->
  </div>
  <div class="page-split">                <!-- фильтры слева от 1024 px -->
    <aside class="page-aside">…</aside>
    <div>…</div>
  </div>
</main>
```

- `.list-grid` — список карточек-строк, две колонки от 1280 px.
- `.card-grid` — сетка фото-карточек (число колонок витрины задаёт админка).
- `.section` + `.section-head` — разделы внутри страницы; `.panel` +
  `.panel-head` + `.panel-body` — блок настроек или формы.

### Маркетинговый режим

Разлинованный лист Pricing/Storage **[разметка]**: каждая полоса во всю ширину с
линией снизу, внутри колонка 1280 с линиями слева и справа.

```html
<section class="frame"><div class="frame-inner frame-hero">…</div></section>
<section class="frame frame-gap"><div class="frame-inner"></div></section>   <!-- пустой ряд с «заклёпками» -->
<section class="frame"><div class="frame-inner">
  <article class="mk-split" data-tone="blue">
    <div class="mk-copy"><span class="mk-eyebrow">Журнал</span><h2 class="mk-h2">…</h2><p class="mk-text">…</p></div>
    <div class="mk-demo">…демонстрация из HTML/CSS/SVG…</div>
  </article>
</div></section>
```

- `.frame-hero` — центрированный заголовок над полем глифов `.glyph-field`
  (как ASCII-фон Pricing, но из символов ColaBike), края гаснут в фон.
- `.mk-title`, `.mk-gradient` (слово в градиенте с размытой копией, Storage),
  `.mk-lead`, `.mk-h2`, `.mk-text`, `.mk-eyebrow` (цветная пилюля темы).
- `.mk-split` — «текст + демонстрация», `.reverse` меняет стороны; `.mk-demo`
  тонирован и несёт два размытых пятна цвета темы (`data-tone`: blue, green,
  amber, pink, violet, teal).
- `.mk-mini` — белые мини-карточки внутри демонстраций, `.mk-mini-label` — моно.
- `.mk-columns` + `.mk-column` — ряд колонок с пунктиром (планы Pricing);
  `.mk-list` — список с галочками; `.mk-steps` — нумерованные шаги.
- Демонстрации — только HTML/CSS/SVG, не скриншоты, и только реально
  существующие возможности. Декоративные элементы не выглядят как рабочие
  кнопки: у них нет курсора-руки и они не в порядке табуляции.

## 7. Компоненты

Все классы — `app/styles/components.css`. Состояния: `:hover`, `:active`,
`:focus-visible` (кольцо 2 px `--focus`), `:disabled` / `aria-disabled`,
`aria-busy`, `aria-invalid`, `aria-pressed` / `aria-selected` / `aria-current`.
`data-state="hover|focus"` фиксирует состояние для UI Kit.

Ключевые действия окрашивают значок при наведении (`data-hover` на кнопке):
`like` — `--like` (красный), `comment` — `--info`, `share` — `--tone-road`,
`follow` и `save` — `--accent-text`. Значок читает `--icon-color`, поэтому
собственный цвет значка в модуле остаётся цветом покоя. Значки подменю берут
оттенок своего раздела (`--nav-tone`), как пункты верхнего уровня.

## 8. Иконки

- Интерфейсные иконки — [Lucide](https://lucide.dev) (`lucide-react`, уже в
  зависимостях), линейные, обводка 1,75, размеры 14 / 16 / 18 (24 в пустых
  состояниях). Цвет наследуется от текста.
- Иконки слотов навигации и действий — компонент `SiteIcon`
  (`app/ui/site-icon.jsx`), таблица `slotIcons`. Администратор может заменить
  любую эмодзи в «Админка → Дизайн → Значки»; эмодзи выводится в том же размере.
  Пустое поле или старое стандартное эмодзи означает «стандартная иконка»
  (`customEmoji` в `lib/ui-emoji.js`).
- Загружаемая графика (фавикон, иллюстрации главной, фоны, изображения типов
  велосипедов, картинки подвала, арт наград) остаётся настройкой админки; код
  не подменяет её зашитыми файлами.

## 9. Движение

- Состояния: цвет, фон, рамка, тень — `--duration-fast` (150 мс), `--ease-out`.
- Появление меню, диалога, тоста — 150–200 мс: прозрачность + сдвиг 2–6 px.
- Маркетинговые блоки могут появляться при прокрутке (`data-reveal`): контент
  виден без JavaScript и при `prefers-reduced-motion: reduce`.
- Демонстрации на `/about` — короткие конечные последовательности, размер
  анимированной области фиксирован (нет сдвига макета).
- Запрещено: бесконечное движение в карточках, параллакс, анимация, мешающая
  чтению. `base.css` глушит всё при `prefers-reduced-motion`.

## 10. Доступность

- Фокус виден всегда (`:focus-visible`, 2 px `--focus`, отступ 2 px; поля —
  синее кольцо 3 px).
- Контраст текста ≥ 4,5:1 в обеих темах (значения в разделе 4). `--text-subtle`
  не используется для текста.
- Размер целей: 36 px на десктопе, 44 px на сенсорных экранах и телефонах
  (правило проекта с #104); маленькие кнопки 28/36 px — только во вторичных
  местах.
- Иконочные кнопки — с `aria-label`; декоративные иконки `aria-hidden`.
- Видимый текст кнопки или ссылки входит в её доступное имя
  (`label-content-name-mismatch`): имя начинается с действия и заканчивается
  тем, что видно («Порядок витрины: Новые»). Подсказка сочетания клавиш
  рисуется CSS и в имя не входит; само сочетание — в `aria-keyshortcuts`.
  Повтор ссылки для мыши (фото карточки ведёт туда же, куда заголовок) —
  `tabindex="-1"` и `aria-hidden="true"`.
- Навигация на телефоне (шапка, `nav`, подвал): цели не меньше 44×44 px.
- Нет горизонтальной прокрутки на 360 px; вкладки прокручиваются внутри себя.
- Модальные окна (`<dialog>`, #129): закрываются кнопкой «Закрыть», Escape и
  нажатием на затемнение, только если нажатие и началось, и закончилось вне
  окна (`useBackdropClose`). Клик по полям окна, по его полосе прокрутки или
  выделение текста, закончившееся снаружи, окно не закрывают. Окно с
  введёнными, но не сохранёнными данными перед закрытием спрашивает
  подтверждение. Если браузер закрыл окно сам (повторный Escape, close
  watcher), оно открывается снова и решение принимает то же правило. В форме
  детали Enter в поле переходит к следующему полю, сохраняет кнопка.

## 13. Отклонения и исключения

Места, где ColaBike сознательно отходит от правил выше или от референса.

- **Строка действий велосипеда** (#121): кнопки 32 px высотой и 13 px текстом,
  как на скриншоте владельца, — и на телефоне тоже, хотя общее правило для
  сенсорных экранов 44 px. Кнопки разнесены промежутком 6 px.
- **Фильтры витрины** — в панели («Фильтры», `dialog.sheet`), а не в боковой
  колонке, как у Datasets: на витрине главное — фотографии, колонка съедала
  бы ширину сетки. Применённые фильтры видны чипами над сеткой.
- **Страница велосипеда** — раскладка фиксирована (#121, #127): настройка
  `detailBlocks` в админке включает и выключает блоки и выбирает их вид, но
  порядок блоков больше не меняет.
- **Карточки велосипедов**: счётчики лайков и комментариев — цели 44 × 44 px
  на всех экранах, хотя визуально это маленькие метки.
- **Самые узкие телефоны** (< 360 px): поля страницы 12 px вместо 16 px, чтобы
  карточка оставалась шириной не меньше 280 px.
- **Кнопка «Поделиться»** вне строки действий велосипеда: на ширине ≤ 600 px
  остаётся только иконка (имя — в `aria-label`).
- **Рекорды**: арт награды 160 px — крупнее обычных иконок, это главный
  элемент карточки рекорда.
- **Письма** (`lib/mail-templates.js`): цвета заданы прямо в HTML, а не
  токенами — почтовые клиенты не поддерживают CSS-переменные; палитра взята из
  светлой темы.
- **Окно входа и регистрации** (#125): почти квадратное окно с иллюстрацией
  слева (загружается в админке) и полями справа; на ширине ≤ 760 px
  иллюстрация становится полосой 128 px над полями.
- **Подвал** (#124): логотипы партнёров слева, название по центру, версии
  справа — собственная раскладка ColaBike, у Hugging Face подвала такого вида
  нет.
- **Lighthouse CI** (необязательный пункт #119) не подключён: доступность
  проверяет axe в e2e; CLS в CI пока не измеряется.
